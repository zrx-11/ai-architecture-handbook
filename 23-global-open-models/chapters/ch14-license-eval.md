# 第 14 章 许可证、数据与评测：开放模型的“隐形架构”

> 难度：中级 · 建议 70 分钟 · 前置：第 1、8、9 章
> 学习目标：能读懂 Apache/MIT/Llama/Gemma/CC-BY-NC/自定义许可的差别；能判断“开放权重”与“开放数据”对复现的意义；能设计一个不被排行榜和污染骗到的选型评测。

## 一句话核心

模型结构决定“能不能跑”，许可证决定“能不能用”，数据决定“能不能复现”，评测决定“值不值得用”。四件事都过关，才叫一个可落地的开放模型。

## 14.1 许可证矩阵

| 许可证 | 商用 | 修改 | 再分发 | 专利 | 典型模型 |
|---|---|---|---|---|---|
| Apache 2.0 | 是 | 是 | 是 | 有明确授予 | Qwen、Mistral 7B、OLMo、Granite、Phi、ERNIE 4.5 |
| MIT | 是 | 是 | 是 | 无明确专利条款 | Phi-3/4、Ling、MiMo、MiniCPM |
| Llama Community | 有条件 | 是 | 有条件 | 有 | Llama 2/3/4 |
| Gemma Terms | 有条件 | 是 | 有条件 | 有 | Gemma 1/2/3 |
| CC-BY-NC | 否 | 是 | 是 | 无 | Command R/R+ |
| 自定义 `other` | 逐条读 | 逐条读 | 逐条读 | 逐条读 | GLM、Kimi、MiniMax、Step、dots |

> “Apache 2.0”不是“随便用”：要保留版权/许可声明、NOTICE，注意商标和专利。商用前让法务读一遍，不要只看标签。

## 14.2 开放权重 vs 开放源码

OSI 的“开源”定义通常要求：自由使用、修改、再分发，且允许商用。很多“开源大模型”只满足前两条，许可证限制商用/再分发；所以更准确的说法是 **open weights**。

| 模型 | 权重 | 代码 | 数据 | 许可证 | 复现训练？ |
|---|---|---|---|---|---|
| OLMo 3 | 是 | 是 | 是 | Apache 2.0 | 可以 |
| Pythia | 是 | 是 | 是（deduped） | Apache 2.0 | 可以 |
| BLOOM | 是 | 是 | 是（部分） | RAIL | 部分 |
| Llama 3 | 是 | 参考实现 | 否 | Llama Community | 不可以 |
| Gemma 3 | 是 | 推理代码 | 否 | Gemma Terms | 不可以 |
| Command R+ | 是 | 推理代码 | 否 | CC-BY-NC | 不可以 |

> 你要做“训练复现/数据研究”，选 OLMo/Pythia/DCLM；你要做“产品部署”，选许可证清楚的模型；不要拿 Llama 做数据复现。

## 14.3 评测的四个陷阱

### 1. 数据污染

Benchmark 题目可能出现在预训练语料里。模型“记得答案”而不是“会推理”。检查方法：

- 看模型卡是否报告 decontamination；
- 用改写/换数字的题目重测；
- 看同一模型在“新题”和“原题”上的差距。

### 2. 排行榜选择偏差

排行榜只测有限任务，且大家会针对性调参。MMLU 高不代表代码强；GSM8K 高不代表长文档强。

### 3. LLM-as-judge 偏差

裁判模型偏好长答案、格式漂亮、和自己风格相似的输出。要用人工抽检、成对比较、位置交换。

### 4. 评测集泄漏到训练

如果你用公开评测集微调，再在同一评测集上报分，分数没有意义。保留一个内部 holdout。

## 14.4 选型矩阵

| 场景 | 显存/硬件 | 优先结构 | 候选 |
|---|---|---|---|
| 手机/端侧 | 4–8GB | 小 dense、4-bit | Gemma E2B/E4B、Phi-4-mini、MiniCPM5、Qwen3.5-0.8B/2B |
| 单卡 24GB | 24GB | 7B–14B dense，4-bit | Phi-4、Qwen3.5-9B、Gemma 3 12B、Mistral Small 3.1 |
| 单卡 48GB | 48GB | 14B–32B dense / 小 MoE | Qwen3.5-27B、Gemma 3 27B、Yi-34B |
| 单机 8 卡 80GB | 640GB | 70B dense / 235B MoE 4-bit | Llama 3.3 70B、Qwen3-235B-A22B |
| 多机 | 多节点 | 400B–2.4T MoE | Llama 4 Maverick、Qwen3.8-2.4T、Mistral Large 4 |
| 长文档 | 大显存 | GQA/MLA/滑窗 | Qwen3.5/3.8、Gemma 3、Kimi K3 |
| 图文 | 24GB+ | 视觉塔 + LLM | Qwen3-VL、InternVL、Gemma 4、MiniCPM-V |
| 商用 | 看许可证 | Apache/MIT 优先 | Qwen、Phi、OLMo、Granite、Ling、MiMo |

> 显存估算：权重 FP16 = 参数量 × 2GB；INT8 ≈ ×1GB；INT4 ≈ ×0.5GB；再留 20–30% 给 KV/激活/框架。MoE 按总参数算权重，不按激活参数。

## 14.5 模型卡审计清单

打开任意模型卡，按这 10 条打勾：

1. 许可证是否明确？商用是否允许？
2. 权重是否完整？是否 gated？
3. 训练数据来源/配比是否公开？
4. 训练 token 数、上下文长度？
5. 架构字段：层数、hidden、Q/KV、专家、top-k？
6.  tokenizer 词表大小、特殊 token？
7. 评测集、分数、是否去污染？
8. 已知偏见/安全限制？
9. 推荐推理框架/量化格式？
10. 版本/日期/联系人？

**缺 3 条以上，这个模型卡不合格；缺许可证，直接放弃商用。**

## 14.6 常见误解

- **“Apache 2.0 就可以随便商用。”** 要保留声明、注意商标/专利；不是法律建议。
- **“开源模型 = 开放数据。”** 多数只开放权重。
- **“排行榜第一就是最好。”** 任务、数据、评测方法都不同。
- **“模型卡写了 128K，就能塞 128K。”** 还要看训练长度、RoPE、KV 显存。
- **“小模型便宜，长上下文也便宜。”** KV 按层数/头数/长度算，小模型也能吃满显存。

## 14.7 自测

1. Apache 2.0、Llama Community、CC-BY-NC 的商用差别是什么？
2. 为什么 OLMo 比 Llama 更适合“训练复现”？
3. 数据污染怎么检测？说出两种方法。
4. 24GB 单卡想跑 14B，FP16 够吗？4-bit 呢？
5. 模型卡缺哪三条你就应该放弃？

> 参考答案：1）Apache 可商用；Llama 有条件商用；CC-BY-NC 禁止商用；2）OLMo 开放数据/代码/日志；3）改写题目重测、检查 decontamination、对比新题/原题；4）FP16 28GB 不够，4-bit 约 7GB 够；5）许可证、数据来源、评测/去污染（或架构/上下文）。

## 14.8 复习锚点

- 许可证矩阵：Apache/MIT/Llama/Gemma/CC-BY-NC/自定义。
- 开放权重 ≠ 开放数据 ≠ 开源。
- 评测四陷阱：污染、排行榜偏差、裁判偏差、泄漏。
- 选型先看显存，再看许可证，再看任务。
