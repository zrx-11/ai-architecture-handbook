# 模式库：六个可复用的判断模式

## 模式 1：许可证先行

**症状**：看到模型强、参数大，立刻下载部署。
**做法**：先查许可证标签 → 读全文 → 判断商用/再分发/衍生模型条款；不通过直接换模型。
**反例**：Command R+ 很强，但 CC-BY-NC 不能商用；Gemma 不是 Apache。

## 模式 2：总参数与激活参数分开

**症状**：把 `2.4T-A95B` 读成“2.4T 激活”，估错算力；或把 MoE 显存按激活算。
**做法**：总参数 → 显存；激活参数 → 每 token 算力；MoE 权重按总参数，KV 按注意力头。
**检查**：`总/激活` 比例越低，容量/算力解耦越激进，但 EP 通信越重。

## 模式 3：先算 KV，再谈长上下文

**症状**：模型卡写 128K/1M，直接上线，结果 OOM。
**做法**：`KV/token = 2 × L × H_kv × d_head × b`；×序列长度 ×batch；再和显存预算比。
**检查**：1M 上下文若朴素 KV 超过数百 GiB，必然用 GQA/MLA/稀疏/量化/分页。

## 模式 4：读 config 而不是读名字

**症状**：名字写 7B，实际层数/宽度/头数与同尺寸不同；名字写 A22B，实际总参 235B。
**做法**：下载 `config.json` → 看 `text_config` → 记录层数、hidden、Q/KV、head_dim、专家、top-k、上下文、rope_scaling。
**检查**：`max_position_embeddings` 可能靠 YaRN 外推，不等于训练长度。

## 模式 5：按架构族识别，而不是按公司

**症状**：以为“Qwen 都是 dense”“Llama 都是 GQA”“Kimi 是 Llama 套壳”。
**做法**：看 `model_type` + `architectures` + 注意力/FFN 字段；公司只是产地。
**检查**：同一公司可能同时有 dense、MoE、线性、混合、多模态。

## 模式 6：评测防污染

**症状**：排行榜分数很高，实际任务很差。
**做法**：查 decontamination → 改写题目/换数字重测 → 保留内部 holdout → 人工抽检 LLM 裁判。
**检查**：分数在新题上大跌，说明可能靠记忆。
