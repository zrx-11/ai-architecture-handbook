00课程概览：图像怎么变成 token

多模态模型要解决一件事：把图像、文档、图表这些非文本输入，变成语言模型能处理的一串 token。这门课从 ViT 的 patch 开始，到 CLIP 的对比学习，再到 DeepSeek-VL、Janus、OCR 系列。

  • 解释 CLIP 的图文对比学习目标。

01ViT：图像切 patch

Transformer 吃的是 token 序列。图像是二维像素网格，不能直接喂。ViT 把图像切成固定大小的 patch，每个 patch 拉平成一个向量，再线性投影成 token。

例：224×224 图像，patch 16×16：

$$\frac{224}{16}\times\frac{224}{16}=14\times14=196\ \text{个 patch}$$

每个 patch 是 $16\times16\times3=768$ 个数，投影到模型维度 $d$，得到 196 个 token。再加一个分类 token 和位置编码。

和 CNN 的区别

结构归纳偏置数据需求
CNN局部性、平移等变中等数据就能学好
ViT少，靠注意力自己学通常需要更多数据/更强增强
patch 越大，token 越少，计算越省，但细节丢得越多。OCR 这类任务通常需要更小的 patch或更高分辨率。

02CLIP：图文对比学习

CLIP 用两个编码器：图像编码器出图像向量，文本编码器出文本向量。一个 batch 里，配对的图文为正样本，其他组合为负样本。

目标：让配对的图文向量相似，不配对的远离。常用 InfoNCE：

$$L=-\log\frac{\exp(\mathbf u_i\cdot\mathbf v_i/\tau)}{\sum_j\exp(\mathbf u_i\cdot\mathbf v_j/\tau)}$$

$\mathbf u_i$ 是第 i 张图的向量，$\mathbf v_j$ 是第 j 段文本的向量，$\tau$ 是温度。

零样本分类

训练好后，把类别名写成文本“a photo of a cat”，算文本向量，和图像向量比相似度，取最高。没有分类头也能分类。

CLIP 学的是“图文匹配”，不是“图像理解一切”。它对细粒度计数、空间关系、OCR 小字并不擅长。

03VL 模型的三段式

大多数视觉语言模型是三段式：

视觉编码器
→
投影/连接层
→
语言模型
  • 视觉编码器：ViT 或 CNN，把图像变成 patch 特征。
  • 连接层：把视觉特征投影到语言模型的维度，变成“视觉 token”。
  • 语言模型：把视觉 token 和文本 token 拼在一起，做自回归生成。

例：图像 196 个 patch，投影后 196 个视觉 token；用户问题 20 个文本 token；拼成 216 个 token 送进 LLM。

VL 模型的能力上限由三块共同决定：视觉编码器看不看得清、连接层对齐得好不好、语言模型会不会用这些 token。

04DeepSeek-VL

DeepSeek-VL 是 DeepSeek 的视觉语言模型系列。它沿用三段式思路，但在数据配比、分辨率处理和训练流程上做了工程取舍。

关键问题

  • 分辨率：高分辨率保留细节，但 token 数暴涨。需要在“看清”和“算得起”之间切。
  • 文档/图表：普通自然图像 patch 不够，需要更高分辨率或切片。
  • 数据：图文对、OCR 数据、图表问答、指令数据要混合，比例影响能力偏向。

DeepSeek-VL2 是后续版本，通常会在视觉编码器、连接方式和数据规模上迭代。课程不逐项报参数，只讲结构逻辑。

看到“VL2 比 VL 强”先问强在哪：自然图像、文档 OCR、图表推理、还是视频？不同 benchmark 侧重不同。

05Janus：理解与生成解耦

多模态模型有两个方向：理解（图 → 文）和生成（文 → 图）。这两个任务对视觉表示的要求冲突：

  • 理解需要语义特征，抽象、耐噪。
  • 生成需要细节特征，保留纹理、颜色、空间结构。

如果共用一个视觉编码器，理解任务会偏向语义，生成任务会丢细节。Janus 的思路是把两条路径解耦：理解用一个编码器，生成用另一个编码器/表示。

$$\text{Janus}=\text{理解路径}(\text{语义编码})+\text{生成路径}(\text{细节编码})$$

这样同一个模型既能答图，也能画图，不用在一条表示上强行折中。

解耦不是“两个模型拼在一起”。训练目标、token 格式、注意力掩码都要设计，否则两条路径会互相干扰。

06OCR 与文档模型

OCR 不是“认字”这么简单。文档里有版面、表格、公式、阅读顺序、手写体。通用 VL 模型在小字和密集表格上容易崩。

DeepSeek-OCR 的思路

  • 高分辨率输入，保住小字。
  • 把版面结构作为 token 的一部分，而不是只做字符识别。
  • 用视觉 token 压缩，减少长文档的序列长度。

OCR2 是后续迭代，重点通常在更复杂的版面、更多语言、更低 token 成本。

任务难在哪模型要求
扫描件文字模糊、倾斜、噪点高分辨率 + 鲁棒预处理
表格行列对齐、合并单元格版面理解 + 结构输出
公式符号、上下标、分式专用词表/LaTeX 输出
手写风格差异大更多手写数据

07Prover 与 Math-V2

DeepSeek 还有一类“专用模型”：数学证明 Prover 系列、数学推理 Math-V2。它们不是通用聊天模型，而是把某一类任务做到很深。

Prover

数学证明要求严格步骤，不能跳。模型需要生成可检查的证明，最好能和证明助手（如 Lean）对接。训练信号来自证明检查器，不是人给的印象分。

Math-V2

数学解题更看重答案正确和步骤可读。常见做法是过程奖励 + 结果奖励结合：答案对给最终分，步骤合理给过程分。

专用模型的价值在“可验证”。证明能被机器检查，答案能对标准答案，训练信号比开放聊天干净得多。

08常见误解与自测

四个误解

  • “多模态就是给 LLM 加个图片输入”：视觉编码器、连接层、训练数据、分辨率策略都要配套。
  • “CLIP 什么图都能理解”：它擅长图文匹配，不擅长细粒度计数和空间推理。
  • “Janus 是两个模型”：是一个模型里的两条路径，共享主干或部分参数。
  • “OCR 只要字识对就行”：版面、表格结构、阅读顺序同样重要。
