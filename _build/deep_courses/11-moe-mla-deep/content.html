00课程概览：为什么大模型要拆专家、压缓存

DeepSeek 的模型越做越大，但每个 token 实际算的参数没有同比例涨。靠的两件事：FFN 拆成 MoE，注意力缓存压成 MLA。这门课把这两块拆开，数字都给你算一遍。

学完你能做到

  • 说清“总参数”和“激活参数”为什么能差一个数量级。
  • 手算一次 top-k 路由的权重归一化。
  • 解释共享专家和负载均衡偏置各自解决什么问题。
  • 用公式算出 V3 128K、V4.1 1M 上下文的 KV cache 大小。
  • 看到一份 config.json，能定位专家数、top-k、MLA 秩和 KV 维度。
前置：知道 FFN 是“线性→激活→线性”，知道矩阵乘法。不熟也没关系，第 1 节会补。

01FFN 是参数大头

Transformer 一层里，注意力负责 token 之间交换信息，FFN 负责对每个 token 单独做变换。注意力的参数是四个 $d\times d$ 矩阵，FFN 通常是两个大矩阵：

$$\text{FFN}(x)=W_2\,\sigma(W_1x)$$

如果 $W_1$ 是 $d\times 4d$，$W_2$ 是 $4d\times d$，这一层 FFN 就有 $8d^2$ 个参数。注意力四个矩阵加起来才 $4d^2$。所以 FFN 占了大头。

结构参数量（每层）占比直觉
注意力（4 个 $d\times d$）$4d^2$约 1/3
FFN（$d\to4d\to d$）$8d^2$约 2/3
MoE 后的 FFN$N$ 个专家 × 单专家参数总参数暴涨，激活不涨

MoE 的思路很直接：既然 FFN 参数最多，就把一个 FFN 拆成很多个专家，每个 token 只走其中几个。总参数可以很大，单 token 的计算量只按被选中的专家算。

一句话：MoE 把“参数容量”和“单 token 计算量”解耦。显存要装下所有专家，算力只付激活的那几个。

02路由与 top-k

每个 token 的隐藏向量 $x$ 先过一个门控，得到每个专家的分数：

$$s_i=x\cdot e_i,\qquad p_i=\sigma(s_i)$$

这里 $e_i$ 是第 $i$ 个专家的门控向量，$\sigma$ 是 sigmoid。然后选分数最高的 $k$ 个专家，只把 token 送给它们。

选中的专家输出按权重加权：

$$y=\sum_{i\in\mathrm{TopK}}w_i\,\text{FFN}_i(x),\qquad w_i=\frac{p_i}{\sum_{j\in\mathrm{TopK}}p_j}$$

手算一次。4 个专家，分数 $p=[0.9,0.5,0.1,-0.2]$，$k=2$。选前两个，权重：

$$w_1=\frac{0.9}{0.9+0.5}=0.643,\qquad w_2=\frac{0.5}{1.4}=0.357$$

输出 $=0.643\,\text{FFN}_1(x)+0.357\,\text{FFN}_2(x)$。权重相加为 1。

门控分数用 sigmoid 而不是 softmax 时，选中的权重还要再归一化一次。不要直接把 sigmoid 值当权重相加，否则输出尺度会随专家数变化。

DeepSeek-V3 是 256 个路由专家 + 1 个共享专家，每个 token 选 8 个路由专家。V4-Pro 扩到 384 路由 + 1 共享，top-6；V4-Flash 是 256 路由 + 1 共享，top-6；V4.1-Flash 是 384 路由 + 1 共享，top-6。

03负载均衡：辅助损失与偏置

路由有个天然问题：模型会偷懒，把大多数 token 都送给少数几个专家。结果是这几个专家被训得很好，其余专家几乎没梯度，容量浪费。

早期做法是往主损失里加辅助损失，惩罚负载集中：

$$\mathcal L_{\mathrm{aux}}=\alpha\sum_i f_i P_i$$

$f_i$ 是分到专家 $i$ 的 token 比例，$P_i$ 是路由概率均值。某个专家分到很多 token，$f_iP_i$ 就大，损失推着路由分散。

但辅助损失和语言建模目标会打架，$\alpha$ 难调。DeepSeek-V3 改成给每个专家一个偏置 $b_i$：

$$s_i=x\cdot e_i+b_i$$

训练时统计负载：负载高的专家把 $b_i$ 调低，负载低的调高。偏置只影响“选不选”，不影响选中后的加权系数。这样不用往主损失里加项，也能把负载拉平。

方案怎么调代价
辅助损失加在总损失里，梯度推动路由和主目标冲突，权重难调
偏置调节按负载统计调 $b_i$，不进入损失需要维护统计量，但主损失干净

04共享专家

只靠路由专家，每个 token 都要重新学一遍“通用语法”。共享专家就是始终激活的 FFN，所有 token 都走它，负责通用知识；路由专家负责细分知识。

$$y=\text{FFN}_{\mathrm{shared}}(x)+\sum_{i\in\mathrm{TopK}}w_i\,\text{FFN}_i(x)$$

DeepSeekMoE 16B 是 64 路由 + 2 共享，top-6；V2 是 160 路由 + 2 共享，top-6；V3 是 256 路由 + 1 共享，top-8。共享专家数量不是越多越好，它增加固定计算量，但不增加路由多样性。

总参数和激活参数分开算。V3 总参数 671B，激活约 37B；V4-Pro 总参数约 1.6T，激活 49B；V4-Flash 284B / 13B；V4.1-Flash 主干 552B + Engram 196B，prefill 8B / decode 16B。数字口径见主手册 09 第 11、13 章。

05KV cache 为什么爆

自回归生成时，每生成一个新 token，都要和前面所有 token 算注意力。为了不重复算，推理框架把历史 K/V 缓存下来，这就是 KV cache。

标准多头注意力（MHA）每 token、每层的缓存字节：

$$2\cdot n_h\cdot d_h\cdot b$$

$n_h$ 是头数，$d_h$ 是每头维度，$b$ 是每元素字节数，前面的 2 是 K 和 V。乘以层数 $L$ 和序列长度 $T$：

$$\text{KV bytes}=2\cdot L\cdot n_h\cdot d_h\cdot b\cdot T$$

拿一个 60 层、128 头、每头 128 维、BF16（2 字节）的模型算 1M 上下文：

$$2\cdot60\cdot128\cdot128\cdot2\cdot10^6\approx3.93\times10^{12}\ \text{B}\approx3.9\ \text{TB}$$

单条 1M 序列就要 3.9 TB，根本放不下。这不是“优化一下”的问题，是架构必须改。

06MLA：缓存潜向量，不缓存完整 K/V

MLA（多头潜在注意力）不再为每个头缓存完整的 K/V，而是先把输入压成一个低维潜向量 $c$，再额外存一个解耦的 RoPE key $k_{pe}$。推理时只缓存这两样，需要 K/V 时再用上投影矩阵还原。

$$c_t=x_tW_{DKV},\qquad k_{pe,t}=x_tW_{KR}$$

V3 的配置：$d=7168$，$d_c=512$，$d_{pe}=64$。每 token 每层缓存 $512+64=576$ 个数，BF16 下：

$$576\cdot2=1152\ \text{B/token/layer}$$

60 层、128K 上下文：

$$1152\cdot60\cdot131072\approx9.06\times10^9\ \text{B}\approx9.21\ \text{GB}$$

和 MHA 的 3.9 TB 比，差了两个数量级。MLA 的代价是每次算 K/V 要多做上投影矩阵乘法，但推理时省下的显存和带宽远大于这点计算。

方案每 token 每层缓存V3 128K 单序列
MHA（128 头 × 128 维）$2\cdot128\cdot128\cdot2=65536$ B约 471 GB
MLA（512 + 64 维）$576\cdot2=1152$ B约 9.21 GB
MLA 缓存的是 $c$ 和 $k_{pe}$，不是还原后的完整 K/V。还原发生在计算时，不占持久显存。看到“缓存 512 维”不要理解成“每层只算 512 维的 K”。

07MTP 与 DSA：训练更密、推理更省

MTP（多 token 预测）在训练时让每个位置额外预测未来第 2 个 token。主模型还是预测下一个 token，但多了一个轻量头，训练信号更密。推理时它也能拿来做投机解码的草稿。

$$\mathcal L=\mathcal L_{\mathrm{next}}+\lambda\,\mathcal L_{t+2}$$

DSA（DeepSeek 稀疏注意力）解决的是长上下文注意力平方复杂度。它用一个轻量索引器给每个 query 和历史 token 打分，只对 top-k 个 token 算注意力：

$$\text{Attn}(q,K,V)=\mathrm{softmax}\left(\frac{qK_{\mathrm{topk}}^T}{\sqrt{d}}\right)V_{\mathrm{topk}}$$

全注意力每层要看 $T$ 个历史 token，复杂度 $O(T^2)$；DSA 只看 $k$ 个，复杂度 $O(Tk)$。当 $T=1$M、$k=2048$，配对数从 $10^{12}$ 降到约 $2.05\times10^9$，差约 488 倍。

DSA 的索引器不是免费的：它自己也要算分。省的是主注意力的二次项，不是把所有计算都变成线性。

选型不要只看总参数。先看激活参数（算力）、再看 KV 账（显存）、再看许可证和任务。V4.1 的全局 KV 约 890 B/token，1M 单序列约 890 MB；50 并发约 44.5 GB。V3 的 128K 约 9.21 GB。两者不是一个量级。

一个实用顺序：任务要不要 1M？要，就看 V4.1/V4；不要，V3.2/V3 的 128K 够用且便宜。再看并发和显存，最后看许可证。不要拿总参数当唯一指标。

09常见误解与自测

先排掉五个误解

  • “MoE 每个 token 走所有专家”：不是。只走 top-k，其他专家不参与这个 token 的计算。
  • “总参数大，推理就慢”：不一定。推理算力看激活参数，显存看总参数；总参数大主要压显存。
  • “MLA 把 K/V 量化成 8 bit”：不是。它是低秩压缩，缓存的是潜向量，不是低比特量化。
  • “MLA 缓存 512 维，所以每层只算 512 维”：还原后还是 128 头 × 128 维，512 只是缓存维度。
  • “DSA 是线性注意力”：不是。它是索引器选 top-k 后再做注意力，复杂度是 $O(Tk)$，不是把所有 token 都压成固定状态。
