# 速查表

## 一、公式与算法

| 场景 | 内容 |
|---|---|
| 并行耗时 | 由最长分支决定：串行 1.2+0.8+1.2+0.8+0.5=5.0 秒；并行 max(1.2,0.8,1.2,1.3)=1.3 秒级 |
| 余弦相似度 | cosθ = (a·b)/(‖a‖‖b‖),只与夹角有关 |
| 余弦手算 | q=(1,2,2), d1=(2,4,4)：内积 18、‖q‖=3、‖d1‖=6 → cos=1 |
| 调用成本 | C = (T_in·p_in + T_out·p_out)/1000 |
| 成本算例 | 1200 输入 @0.02、300 输出 @0.06 → (24+18)/1000 = 0.042 元 |
| 分层路由省钱 | 50,000 次/日 × 0.042 = 2100 元；70% 走 1/5 单价 → 约 924 元，省 56% |
| 自洽投票 | P(至少一次正确) = 1-(1-p)^n;p=0.3、n=5 → 83.2% |
| ToT 候选数 | b^d;b=3、d=3 → 27 条路径 |
| N×M 集成 | 4 应用 × 6 系统 = 24 套；MCP 后 4+6 = 10 |
| 审核人力 | 200 万/日，85% 自动、12% 人工（24 万）→ 约 120 人（2000 条/人日） |
| 轨迹查准/查全 | 实际 6 步中 4 步属于理想 4 步 → 查准 4/6=66.7%,查全 4/4=100% |
| 上下文压缩 | 40 轮 × 300 token ≈ 12,000 → 压到约 2,500 |

## 二、判据速记

| 问题 | 判据 |
|---|---|
| 要不要拆步骤 | 这一步的输出能不能被独立验证 |
| 要不要并行 | B 需不需要 A 的输出 |
| 要不要反思 | 有没有外部判据 + 错误代价高不高 |
| 要不要多智能体 | 上下文拥挤 / 能力冲突 / 错误无对照，三个占一个才拆 |
| 要不要上 MCP | 工具是否固定少量；是否需要跨应用复用与动态发现 |
| 要不要插人 | 错了能不能撤回 |
| 用 RAG 还是微调 | 知识是否频繁更新、是否需要引用来源 |
| 用 CoT 还是 ReAct | 信息是否在推理过程中才暴露 |
| 用 ToT | 选择关键、搜索空间不大、有估值手段 |
| 优先级怎么排 | 五标准里"就绪"是一票否决 |

## 三、参数经验值

| 参数 | 建议值 | 依据 |
|---|---|---|
| 反思轮次上限 | 2~3 | 第 3 轮后多在改措辞 |
| RAG top_k | 5 左右 | 再多会稀释注意力 |
| RAG 相似度阈值 | 0.7 起，按语料校准 | 只按 k 不设阈值会硬塞噪声 |
| 暴露工具数量 | 3~5 个/组 | 超过十几个选错率上升 |
| 重规划触发 | 连续失败 3 次、判据不符、约束变化 | 三者任一 |
| P0 配额 | ≤20% 并发槽位 | 防优先级通胀 |
| 温度 | 需要多样性采样时 >0 | 温度 0 会毁掉自洽投票的独立性 |

## 四、ADK 编排构件

| 构件 | 作用 |
|---|---|
| SequentialAgent | 顺序执行子智能体 |
| ParallelAgent | 并行执行 |
| LoopAgent | 循环，需终止条件 + 最大迭代 |
| 智能体即工具 | 把子智能体包成工具，实现层级 |
| MCPToolset | 接 MCP 服务器，可 `tool_filter` 限权 |
| 工具调用前回调 | 校验参数，如 user_id 与会话一致 |

## 五、常见错误对照

| 症状 | 多半是 | 先改哪里 |
|---|---|---|
| 答案对但过程乱 | 缺轨迹评估 | 加日志与理想路径 |
| 越改越差 | 反思无外判据 | 引入测试/原文/清单 |
| 简单问题也慢 | 没有路由 | 加复杂度分类与便宜模型 |
| 成本失控 | 上下文不裁剪 | 剪枝 + 分层路由 |
| 重复副作用 | 非幂等 + 盲目重试 | 幂等键 + 状态前置检查 |
| 工具总是选错 | 工具太多、描述没写"何时别用" | 分组暴露 + 负向说明 |
