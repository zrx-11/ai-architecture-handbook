# 术语表

| 术语 | 白话定义 | 首次出现 |
|---|---|---|
| 智能体 | 能感知环境、依据目标决策并自主行动的软件系统。 | ch00 |
| 认知引擎 | 智能体里负责理解与生成的大模型，只提供认知能力，不提供结构。 | ch00 |
| 自主等级 | 按能力复杂度划分的 Level 0~3：纯模型、加工具、加规划、加协作。 | ch00 |
| 上下文窗口 | 模型一次能处理的最大 token 数，含输入与输出。 | ch00 |
| 上下文工程 | 为当前任务动态组装背景信息（检索、工具输出、隐式数据），区别于静态系统提示。 | ch01 |
| 提示链 | 把整体任务拆成若干可验证的局部转换，逐步传递。 | ch01 |
| 输出契约 | 规定上一步交给下一步的结构、取值约束与失败语义。 | ch01 |
| 路由 | 运行时根据输入决定走哪条路径，而不是把路径写死。 | ch02 |
| 兜底分支 | 路由必须保留的默认路径，防止没有匹配分支时直接失败。 | ch02 |
| 判别式路由 | 用训练好的分类器决定路径，知识固化在权重里。 | ch02 |
| 截面并行 | 把互不依赖的子任务同时执行，用时间换吞吐。 | ch03 |
| 投票并行 | 同一任务多次采样后聚合，用冗余换可靠性。 | ch03 |
| 反思 | 带一条回边的控制结构：产出→按判据检查→改→直到通过或达上限。 | ch04 |
| 外部判据 | 来自产出者之外的判断依据，如测试、原文、清单、规则。 | ch04 |
| 过度修正 | 反思中没有可靠判据时越改越偏的一种退化。 | ch04 |
| 工具使用循环 | 定义→决策→生成参数→框架执行→观察结果→再决策的闭环。 | ch05 |
| 工具 schema | 工具的名称、参数、类型与使用条件的结构化声明。 | ch05 |
| ReAct | 思考→行动→观察→再思考的循环，边走边查。 | ch05 |
| 规划 | 把高层目标拆成可执行步骤，并处理依赖与重规划。 | ch06 |
| DAG 计划 | 用有向无环图表示步骤与依赖，允许并行与部分重排。 | ch06 |
| 重规划 | 执行中因失败、判据不符或约束变化而修改后续步骤。 | ch06 |
| 多智能体协作 | 多个专职智能体分工协作完成单智能体难以完成的任务。 | ch07 |
| 监督者拓扑 | 由一个协调者分配任务并汇总结果的结构，协调者是单点。 | ch07 |
| 批评-审查者 | 一方产出、另一方按六类标准评审并回传修订意见的结构。 | ch07 |
| 共享状态（黑板） | 多个智能体读写同一块状态来协作，需处理并发与责任边界。 | ch07 |
| 智能体即工具 | 把子智能体包装成工具，用已有的工具调用机制实现层级结构。 | ch07 |
| 短期记忆 | 会话内的上下文，受容量、易失、重复计费三重限制。 | ch08 |
| 长期记忆 | 跨会话保存的外部存储，分语义、情景、程序性三类。 | ch08 |
| 语义记忆 | 记住事实（如用户偏好、公司政策）。 | ch08 |
| 情景记忆 | 记住经历（如上次那次失败的处理过程）。 | ch08 |
| 程序性记忆 | 记住规则与做法，可被反思结果更新。 | ch08 |
| state 键前缀 | 用 user:/app:/temp: 等前缀决定状态的生效范围。 | ch08 |
| 在线学习 | 用持续到来的新数据不断更新行为。 | ch09 |
| PPO | 强化学习算法，用裁剪限制每次策略更新的幅度。 | ch09 |
| DPO | 直接用偏好数据优化策略，跳过奖励模型。 | ch09 |
| SICA | 能修改自身代码的智能体，靠版本归档与基准测试迭代。 | ch09 |
| MCP | 模型上下文协议，用客户端-服务器架构标准化模型与外部能力的对接。 | ch10 |
| 资源（Resource） | MCP 暴露的静态数据，如文档、数据库记录。 | ch10 |
| 工具（Tool） | MCP 暴露的可执行功能，有副作用。 | ch10 |
| JSON-RPC over STDIO | MCP 的本地传输方式，走进程间通信。 | ch10 |
| Streamable HTTP | MCP 的远程传输方式，配合 SSE 支持长连接。 | ch10 |
| 目标可判定 | 目标能被机器或人明确判断是否达成，含指标、阈值、时限、判定者。 | ch11 |
| 监控四观测 | 对行为、环境、工具输出、判据的持续观察。 | ch11 |
| 幂等 | 同一操作执行一次与多次结果相同，是重试安全的前提。 | ch12 |
| 降级链 | 逐级降低服务质量的备用路径，如精确地址→城市级→致歉。 | ch12 |
| 升级策略 | 超出能力时按既定协议转给人或更高级系统。 | ch12 |
| 人类参与（HITL） | 在机器决策边界上插入人类审批、干预或纠正。 | ch13 |
| Human-on-the-loop | 人定规则、AI 实时执行，异常时人才介入。 | ch13 |
| RAG | 检索增强生成：先检索相关材料，再把它放进上下文让模型作答。 | ch14 |
| 分块（chunking） | 把长文档切成检索单元，块大小影响召回粒度。 | ch14 |
| 嵌入 | 把文本映射为高维向量，语义相近则方向相近。 | ch14 |
| 余弦相似度 | 两个向量夹角的余弦，只与方向有关、与长度无关。 | ch14 |
| 混合检索 | 向量检索与关键词检索（如 BM25）结合，互补短板。 | ch14 |
| GraphRAG | 在知识图谱上检索，效果高度依赖图的质量。 | ch14 |
| A2A | 智能体间通信的开放标准，基于 HTTP 与 JSON-RPC。 | ch15 |
| Agent Card | 智能体的数字身份声明：端点、能力、技能、认证要求。 | ch15 |
| artifact | A2A 任务中被产出的结果对象，可流式传输。 | ch15 |
| 推理扩展定律 | 在推理阶段增加计算（多采样、多路径）可提升准确率，小模型也能受益。 | ch16 |
| 成本公式 | 单次调用成本 = (输入 token×输入单价 + 输出 token×输出单价)/1000。 | ch16 |
| 优雅降级 | 资源不足时主动降低服务质量以维持可用。 | ch16 |
| CoT | 链式思维：要求模型显式写出中间推理步骤。 | ch17 |
| ToT | 树式思维：并行探索多条推理路径并评估选择。 | ch17 |
| PALMs | 让模型写代码并执行，把精确计算交给确定性环境。 | ch17 |
| 自洽性投票 | 多次采样后按多数结果聚合，用 1-(1-p)^n 提升成功率。 | ch17 |
| 护栏 | 在输入、工具、输出等位置设置的强制关卡。 | ch18 |
| 提示注入 | 把指令藏进数据里让模型执行，是护栏要防的主要攻击。 | ch18 |
| 结构性护栏 | 校验输出结构（字段、类型）而非内容合规的护栏。 | ch18 |
| 轨迹评估 | 把实际步骤序列与理想路径对比来评估过程质量。 | ch19 |
| LLM-as-a-Judge | 用另一个模型按预设标准给输出打分。 | ch19 |
| 漂移 | 输入分布或环境变化导致性能随时间下降。 | ch19 |
| 优先级老化 | 任务每等待一个周期就提升优先级，防止饥饿。 | ch20 |
| 优先级通胀 | 所有任务都自称紧急导致优先级失去区分度。 | ch20 |
| 依赖反转 | 高优先级任务被低优先级前置阻塞，需要传递提升。 | ch20 |
| 探索与发现 | 在解空间未知、评分函数缺失的环境中生成并筛选新假设。 | ch21 |
| Elo 排名 | 只能两两比较时使用的相对评级机制。 | ch21 |
| ACI | 智能体-计算机接口：通过视觉感知与鼠标键盘操作 GUI。 | ch25 |
| vibe coding | 用高层目标与自然语言反馈驱动 AI 写代码的协作方式。 | ch25 |
