# 综合检验建议

## 跨书整合题

### 题 1：一页“瓶颈迁移”说明
- 涉及：基础篇第 5 章、论文篇第 8–9 章、架构篇第 10 章
- 要求：用不超过 800 字说明 V3/R1 → V4 → V4.1 各自被什么瓶颈逼着改架构。每代至少引用两个数字（KV cache、FLOPs、压缩率、激活参数均可）。
- 评分要点：
  1. 三代的瓶颈判断正确，不把 R1 说成架构升级。
  2. 每个数字有单位、有对比对象。
  3. 能说出至少一项代价（精度、工程复杂度、显存）。

### 题 2：1M 上下文选型报告
- 涉及：论文篇第 9 章、架构篇第 13 章
- 要求：假设 1M 输入、5K 输出、1 万请求/日、50 并发、10% 含图。比较 V3.2、V4-Flash、V4-Pro、V4.1-Flash，给出主模型与路由策略。必须计算单请求 KV 与 50 并发总 KV。
- 评分要点：
  1. 全局 KV 与持久 KV 分开算。
  2. 区分 FLOPs 与延迟，不把论文估算当实测。
  3. 选型有取舍，不是“全上最强”。
  4. 风险清单具体，含精度与长文本检索验证。

### 题 3：论文审稿：找出过度声明
- 涉及：论文篇第 8–9 章
- 要求：下面这句话有三处不严谨，逐条指出并给出修正：“V4.1-Flash 全面超越 V4-Pro，因为它的 KV cache 只有 890 B/token，所以推理成本最低。”
- 评分要点：
  1. 指出 V4.1 目前只有 Flash，论文对标的是 V4-Flash。
  2. 指出 890 B 是全局 KV，不含持久 KV、SWA、Engram。
  3. 指出 KV 小不等于总成本低，还要看 FLOPs、带宽、激活参数、硬件利用率。

### 题 4：为什么测试集不能反复挑模型
- 涉及：机器学习基础第 2 章
- 要求：用 1000 个样本、5 折交叉验证的例子，说明验证集与测试集的分工；再解释“用测试集反复挑模型”为什么会高估性能。
- 评分要点：
  1. 说清验证集参与调参、测试集只做最终报告。
  2. 算出 5 折时每折训练/验证样本数。
  3. 指出信息泄露导致泛化估计偏乐观。

### 题 5：SVM 的核心不是“画一条线”
- 涉及：机器学习基础第 6 章、SVM 深潜第 1–8 节
- 要求：从最大间隔写到对偶问题，再说明核技巧为什么能避免显式高维映射。给一个线性不可分的小例子，比较线性 SVM 与 RBF 核的行为。
- 评分要点：
  1. 写出间隔与支持向量的关系。
  2. 对偶里数据只以内积出现。
  3. 说明核函数替代内积的条件。
  4. 能说出 C 与 γ 变大/变小的后果。

### 题 6：Transformer 的张量形状追踪
- 涉及：基础篇第 3–4 章、Transformer 深潜第 4–9 节
- 要求：假设 batch=2、序列长度=4、d_model=8、头数=2，逐层写出 Q/K/V、注意力分数、多头拼接、FFN 的形状。标出每个矩阵乘法的维度。
- 评分要点：

## 进阶路线

1. **理论路线**：补线性代数、概率论、强化学习（策略梯度、PPO/GRPO）、最优化，目标是能自己推导论文公式。
2. **工程路线**：读 `modeling_deepseek.py`、FlashMLA、DeepEP、TileLang 算子，搭一个小规模 MoE/MLA 模型跑通前向。
3. **论文写作路线**：按“五问”拆 5 篇同领域论文，写对比表格，练习区分“作者解释”与“实验结论”。

### 题 7：给 2.4T-A95B 算一笔 1M 上下文的账
- 涉及：全球分册第 4、11、13 章
- 要求：用 Qwen3.8-2.4T 的 92 层、64 Q/4 KV、head_dim 256，算 1M token 的单序列 KV（FP16）；再解释 512 专家 top-10 的激活比例为什么不是 10/512。给出至少两条把 KV 压下去的办法。
- 评分要点：
  1. KV/token = 2×92×4×256×2 = 376,832 B ≈ 368 KiB；1M ≈ 368 GiB。
  2. 激活比例按专家宽度/共享专家/注意力一起算，不能用 top-k/专家数直接代替。
  3. 能说出 GQA/MLA、稀疏/滑窗、KV 量化、分页中的至少两条。

### 题 8：许可证选型
- 涉及：全球分册第 14 章
- 要求：某团队要把一个开放模型做成付费 API，候选是 Llama 3.3 70B、Gemma 3 27B、Mistral Small 4、Command R+。先判断哪些能商用，再给出两个可行候选和两个被排除理由。
- 评分要点：
  1. Command R+ 是 CC-BY-NC，不能直接商用。
  2. Llama/Gemma 是自定义社区条款，不是 Apache/MIT；要读再分发/命名/衍生条款。
  3. 不把“权重可下载”当成“商用许可”。

### 题 9：读两份 config，判断谁更贵
- 涉及：全球分册第 3–4、15 章
- 要求：对比 Llama 3.3 70B（80 层、8192、64/8、head_dim 128）与 Qwen3.8-27B（64 层、5120、24/4、head_dim 256），各算 FP16 权重显存与 32K 单序列 KV，说明哪个更适合单卡 80GB。
- 评分要点：
  1. 权重：70B×2=140GB；27B×2=54GB。
  2. KV：Llama 0.3125 MiB/token×32K≈10 GiB；Qwen 0.25 MiB/token×32K≈8 GiB。
  3. 单卡 80GB 只能放 27B（权重 54GB + KV 8GiB + 激活），70B 需要量化或多卡。
