00课程概览：把“大模型”算成数字

这门课不讨论模型聪不聪明，只算账：训练要多少 FLOPs、推理要多少显存、并发能开多少、什么模型在什么负载下划算。所有例子都能用纸笔复算。

学完你能做到

  • 用 $6ND$ 估算训练 FLOPs，并换算成 GPU 天数。
  • 用公式算 KV cache，判断一张卡能放多长的上下文。
  • 区分 prefill 和 decode 的瓶颈：一个吃算力，一个吃带宽。
  • 说清 DP、TP、PP、EP 各自切什么、通信什么。
  • 在延迟、吞吐、上下文、许可证之间做选型。
前置：会科学计数法、会乘除。公式里的 $10^{12}$ 读作“万亿”，$10^9$ 读作“十亿”。

01参数量与显存

先分清三个数：总参数、激活参数、训练状态。推理时显存主要装权重和 KV cache；训练时还要装梯度、优化器状态和激活值。

精度每参数字节7B 模型权重
FP32428 GB
BF16 / FP16214 GB
FP817 GB
FP40.53.5 GB

训练用 Adam，每个参数通常要存：权重、梯度、一阶动量、二阶动量。FP32 下是 16 字节/参数：

$$\text{训练状态}\approx16P\ \text{字节}$$

7B 参数就是 112 GB，还没算激活值和临时缓冲。单卡放不下，所以要并行、要 ZeRO、要混合精度。

“模型 7B，所以 14 GB 显存就够”只在纯推理、BF16、没有 KV cache 的理想情况下成立。实际还要留出 KV cache、框架开销和碎片。

02训练 FLOPs：6ND

训练一个 transformer，粗略估算：每个参数、每个 token 前向约 2 次浮点运算，反向约 4 次，合计 6 次。

$$\text{FLOPs}\approx6ND$$

$N$ 是参数量，$D$ 是训练 token 数。这个公式忽略注意力随上下文增长的二次项，短上下文够用。

例子：7B 参数，训练 1B token。

$$6\cdot7\times10^9\cdot1\times10^9=4.2\times10^{19}\ \text{FLOPs}$$

一张 300 TFLOPS 的卡，实际利用率 50%，有效算力 $1.5\times10^{14}$ FLOP/s：

$$\frac{4.2\times10^{19}}{1.5\times10^{14}}\approx2.8\times10^5\ \text{s}\approx3.2\ \text{天}$$

这是“一张卡”的时间。实际用几百张卡，还要扣通信、故障、数据加载，不是线性缩放。

$6ND$ 是量级估算，不是账单。MoE 只用激活参数算前向，但总参数影响显存；上下文很长时，注意力的 $T^2$ 项会变成大头。

03KV cache 公式

推理时缓存历史 K/V，每个 token、每层、每个 KV 头存两个向量：

$$\text{KV bytes}=2\cdot L\cdot n_{kv}\cdot d_h\cdot b\cdot T\cdot B$$

$L$ 层，$n_{kv}$ 个 KV 头，$d_h$ 每头维度，$b$ 字节数，$T$ 序列长度，$B$ 并发数。

例子：32 层、32 个 KV 头、每头 128 维、BF16、4096 上下文、单序列：

$$2\cdot32\cdot32\cdot128\cdot2\cdot4096$$
$$\approx2.15\times10^9\ \text{B}\approx2\ \text{GB}$$

10 个并发就是 20 GB。上下文翻倍，KV 翻倍；并发翻倍，也翻倍。

模型每 token 全局 KV128K 单序列1M 单序列
V3（MLA）约 70,272 B约 9.21 GB约 73.7 GB
V3.2（DSA 全注意力等价）约 367 KB约 48.1 GB约 385 GB
V4.1（CED/CSA2）约 890 B约 114 MB约 890 MB
不同模型的“每 token KV”口径不同：MLA 只算潜向量，DSA 还要算索引器，V4.1 的 890 B 是论文口径的全局 KV。比较时先确认口径，不要拿不同东西相除。

04prefill 与 decode

推理分两段。prefill 把整段输入一次性读进去，建立 KV cache；decode 一个 token 一个 token 生成。

阶段并行度主要瓶颈优化方向
prefill高，整段并行算力（FLOPs）更好的矩阵乘、FlashAttention、FP8
decode低，逐 token显存带宽（KV 读取）KV 压缩、批处理、投机解码

decode 每生成一个 token，都要把历史 KV 从显存读一遍。算术强度低：算的 FLOPs 少，搬的字节多。GPU 的算力经常闲置，等显存。

$$\text{算术强度}=\frac{\text{FLOPs}}{\text{Bytes}}$$

算术强度低于机器的 ridge point，就是 memory-bound；高于它，才是 compute-bound。decode 通常远低于 ridge point，所以“FLOPs 没用满”不代表代码写得差。

05并行：DP、TP、PP、EP

方式切什么通信什么适合
DP（数据并行）切 batch，每卡一份完整模型梯度 all-reduce模型能单卡放下
TP（张量并行）切矩阵的列/行每层 all-reduce单层太大，节点内高带宽
PP（流水并行）切层，不同卡放不同层激活值点对点传输层数多，跨节点
EP（专家并行）不同专家放不同卡token 路由 all-to-allMoE 专家多

实际训练是组合：TP 放在节点内（NVLink），PP 和 DP 跨节点，EP 按专家分布。并行的难点不是切，是切完之后通信别把算力吃光。

TP 的 all-reduce 很频繁，适合高带宽互联；PP 有空泡（bubble），需要 micro-batch 填；EP 的 all-to-all 对网络压力大。没有一种并行适合所有集群。

06量化：FP16、FP8、FP4

量化就是把权重/激活用更少的位表示。显存和带宽下降，算力也可能提升，代价是数值误差。

格式位宽特点常见用途
FP3232精度高，显存大训练主权重、优化器状态
BF1616动态范围大，训练稳定训练/推理常用
FP1616精度高，范围小，易溢出推理、混合精度
FP88需要缩放因子H100 等新硬件训练/推理
FP44压缩率高，误差大权重-only 推理、特定硬件

量化不是“把数字四舍五入”这么简单。FP8 要 per-tensor 或 per-channel 的 scale，FP4 通常要分组缩放和校准。校准数据选错，精度会掉得很厉害。

量化收益要先看瓶颈。decode 是 memory-bound，权重量化能直接提速；prefill 是 compute-bound，FP8 的算力收益更关键。不要以为量化一定快。

07选型：延迟、吞吐、上下文、成本

选型不是“哪个参数大哪个好”。先列约束，再排优先级。

场景第一指标建议
单用户长文档问答首 token 延迟、上下文V4.1/V4，1M 上下文，KV 压缩
高并发 API吞吐、每 token 成本V4-Flash 或 V3.2，批处理
代码补全低延迟、短上下文小激活模型，投机解码
离线批量推理总成本大 batch、FP8/FP4、老一代

一个简化的成本式：

$$\text{每 token 成本}\approx\frac{\text{GPU 小时价}\times\text{占用卡数}}{\text{每小时生成 token 数}}$$

上下文越长，KV 越大，能并发的序列越少，单位成本越高。长上下文不是免费的。

先问四个问题：要多长上下文？多少并发？首 token 延迟卡不卡？许可证能不能用？四个答案定完，再谈参数和排名。

08常见误解与自测

先排掉五个误解

  • “参数量翻倍，推理速度减半”：不一定。看激活参数、带宽和批处理。
  • “KV cache 只和上下文有关”：还和层数、KV 头数、每头维度、精度、并发有关。
  • “decode 慢是因为 GPU 算力不够”：多数时候是显存带宽不够。
  • “量化一定更快”：compute-bound 场景不一定，校准不好还会掉精度。
  • “并行度越高越快”：通信和空泡会把收益吃掉。
