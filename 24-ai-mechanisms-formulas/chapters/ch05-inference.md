# 第 5 章：推理系统（71–86）

推理的瓶颈不止“算得慢”，更多时候是“权重和 KV 搬得慢”。这一组机制几乎都在解决同一个约束：decode 每步只生成一个 token，算力单元吃不饱。

## 一句话核心

prefill 是算力密集，decode 是带宽密集；把两段混在一张卡上，就会互相拖累。

## 学习目标

- 能解释 KV cache 为什么随上下文线性增长。
- 能区分 PagedAttention、连续批处理、PD 分离各自优化哪一段。
- 能判断一个推理优化是省显存、省带宽，还是省算力。

## 机制表

| # | 机制 | 一句话 | 代价或边界 |
|---|---|---|---|
| 71 | KV cache | 缓存历史 token 的 K/V，每步只算新 token 并追加 | 显存随上下文线性涨；长上下文贵的直接原因 |
| 72 | 提示缓存 | 前缀逐 token 一致才命中，命中部分不重算 prefill | 可变内容必须放最后，否则永远不命中 |
| 73 | PagedAttention | 借虚拟内存分页，把 KV 切成固定块按需分配 | 显存利用率从五六成提到九成以上，吞吐翻倍 |
| 74 | 连续批处理 | 每轮踢掉完成序列、补进新请求，prefill 与 decode 混批 | 填满 decode 空转；显存按峰值预留，长请求延迟被拉长 |
| 75 | prefill/decode 分离 | 预填充与解码各用一组硬件，中间传 KV | 让两种负载各自吃满；跨机 KV 传输可能吃掉收益 |
| 76 | FlashAttention | 分块计算，n×n 注意力不物化，用重算换显存 | 数学等价；省显存与 IO，不减 FLOPs |
| 77 | 训练后量化 PTQ | 把 fp16 权重压到 int4/int8，逐组缩放保护异常值 | 位宽减半，带宽减半；任务准确率要单独验 |
| 78 | KV cache 量化 | 把缓存 K/V 从 fp16 压到 int8/int4 | 长上下文显存减半；少数关键层压坏会拖累整段注意力 |
| 79 | 模型路由 | 小分类器判断难度，简单请求走小模型，难请求升级 | 路由信号要含成本；阈值决定升级频率 |
| 80 | 上下文压缩 | 窗口到七八成时滑动、摘要或分层存储 | 摘要不可逆；关键实体、数字要另存 |
| 81 | 分块预填充 | 长提示切块，与新请求交替调度 | 首 token 延迟略增，吞吐显著上升 |
| 82 | KV cache 驱逐 | 显存不够时丢最久远或按重要性丢 | 必须保留开头 Attention Sink，否则注意力失准 |
| 83 | 投机解码变体 | Medusa 加多个解码头，EAGLE 用特征层做草稿 | 省一次部署；接受率仍决定收益 |
| 84 | 批次调度与公平性 | 先来先服务、最短剩余优先、公平份额 | 选哪种取决于 SLA 写平均延迟还是 P99 |
| 85 | 分离式部署 | prefill 池与 decode 池分开建集群 | 工程难点在 KV 跨机传输，网络慢就白省 |
| 86 | 测试时计算 | 把“想多久”当成可调超参，预算换准确率 | 收益沿对数曲线饱和；不是无限加算力就更好 |

## 推理优化的判断顺序

1. 先看 TTFT 还是 TPOT 超标。
2. TTFT 超标先看 prefill 算力、分块与批处理。
3. TPOT 超标先看权重带宽、KV 读放大、量化与投机解码。
4. 并发上不去再看 KV 分页、驱逐与 PD 分离。

## 常见误解

- “KV cache 只是缓存，不占多少显存。”长上下文时它常超过权重。
- “量化一定更快。”大 batch、算力受限时，收益会消失。
- “连续批处理只影响吞吐。”它会拉长长请求的尾延迟。

## 自测

1. PagedAttention 解决的是碎片还是计算？
2. 为什么 PD 分离能同时优化 TTFT 和 TPOT？
3. 上下文压缩丢掉的细节，为什么不能靠摘要补回来？

## 复习锚点

- prefill 算力，decode 带宽。
- KV 是变动成本，权重是固定成本。
- 优化前先分清 TTFT 与 TPOT。
