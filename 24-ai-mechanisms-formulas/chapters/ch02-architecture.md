# 第 2 章：模型架构机制（1–21）

这一组回答“一个 token 从进入模型到离开模型，中间被哪些结构处理过”。先记住每个结构替换了谁、付出了什么。

## 一句话核心

架构演进不是堆新名词，而是在“表达力、显存、带宽、通信、长度”之间换账。

## 学习目标

- 能从 BPE 讲到 MoE，不漏掉归一化、残差、位置编码。
- 能解释 MQA/GQA、MLA、Mamba、KDA 分别在省哪一份账。
- 能区分“训练时并行”和“推理时内存恒定”这两种设计目标。

## 机制表

| # | 机制 | 一句话 | 代价或边界 |
|---|---|---|---|
| 1 | BPE 分词 | 从字符表开始，反复合并最高频相邻对，把高频词压成一个 token，生词拆成词根 | 词表决定计费与上下文；模型看不见单个字母 |
| 2 | 字节级分词 BLT | 不分词，直接吃字节流，再用动态 patch 压成块 | 绕开词表外与多语言不平等；序列更长、训练更贵 |
| 3 | 嵌入层与输出头 | token id 查表成向量；最后一层隐藏状态乘回词表维度打分 | 词表大时这块参数不小；输入输出常共享权重 |
| 4 | RMSNorm / LayerNorm | 每个 token 的激活做归一化，稳住深层网络的尺度 | LayerNorm 多一次减均值；RMSNorm 更省、更常用 |
| 5 | 自注意力 | 每个 token 用自己的 Q 与所有 K 打分，softmax 后加权求和 V | 注意力的真正优势是一次矩阵乘并行，不只是路径短 |
| 6 | 因果掩码 | 把未来位置的分数置为负无穷，禁止看见后文 | 去掉它，训练时模型直接抄答案 |
| 7 | RoPE | 把 Q、K 按位置旋转，让注意力只依赖相对位移 | 超出训练长度仍会退化，要配 YaRN/NTK 缩放 |
| 8 | 长度外推 YaRN / NTK | 缩放旋转角或改 base，把没见过的位置拉回训练分布 | 不改权重就能拉长上下文，但不是免费的质量提升 |
| 9 | MQA / GQA | 多个查询头共享同一组 K/V，压缩 KV cache | MQA 省最多但质量掉；GQA 是常用折中 |
| 10 | 残差连接 | 把子层输入直接加到输出，给梯度开一条直通路 | 输出尺度会累积，必须配归一化 |
| 11 | 前馈层与 SwiGLU | 逐 token 的两层 MLP，先升维再降维；SwiGLU 多一个门控矩阵 | block 里参数最多的一块，也是 MoE 替换的对象 |
| 12 | MoE | 把 FFN 拆成多个专家，每 token 只激活 top-k 个 | 总参数换容量，激活参数换成本；路由均衡与 all-to-all 是代价 |
| 13 | 滑动窗口与稀疏注意力 | 每个 token 只看最近 N 个或少量关键位置 | 注意力从平方变线性；远处信息要靠层数、检索或全局 token 补 |
| 14 | MLA | 不缓存完整 K/V，把每个 token 的 K/V 压成低秩潜向量，用时再投影回来 | KV 显存降数倍；每次多一次矩阵乘 |
| 15 | Mamba / 状态空间 | 用固定大小隐状态随序列滚动，不做全序列两两比较 | 推理内存恒定、计算线性；长程精确召回不如注意力 |
| 16 | RWKV | 线性注意力加循环门控，训练并行、推理递推 | 固定状态省显存；表达力与检索能力有限 |
| 17 | Kimi Delta Attention KDA | 多数层换线性注意力，只维护固定状态，隔几层保留全局注意力 | 线性省算力；全局层是表达能力兜底 |
| 18 | 注意力残差 AttnRes | 让每层直接去前面任意层取所需信息，而不是只靠标准残差 | 省掉逐层稀释；实现与块划分更复杂 |
| 19 | Engram 条件记忆 | 把事实性知识放进可检索的外部记忆，参数专心做推理 | 不等于 RAG：检索在模型内部，由训练决定何时取 |
| 20 | 多模态投影层 | 把视觉编码器的 patch 向量翻译成语言模型能读的 token | 多模态天花板常在这个翻译层，不在视觉塔 |
| 21 | Attention Sink | 模型会把大量注意力分给序列开头几个 token，作为“不用看任何东西”的落脚点 | KV 驱逐必须保留开头几个 token，否则注意力失准 |

## 三条主线

1. **token 化与位置**：BPE/BLT 决定词表，RoPE/YaRN 决定长度，嵌入与输出头决定参数。
2. **块内结构**：归一化 → 注意力 → 残差 → FFN；MoE 换掉 FFN，MLA/GQA 换掉 K/V 缓存。
3. **替代路线**：滑窗、稀疏、Mamba、RWKV、KDA 都在问同一个问题——能不能不存完整 KV。

## 常见误解

- “MLA 省的是注意力计算。”它主要省 KV cache 的显存与带宽，计算反而多一次投影。
- “MoE 的总参数就是每 token 的计算量。”总参数看显存，激活参数才看 FLOPs。
- “Mamba 完全替代 Transformer。”纯 SSM 的长程精确召回仍有短板，主流是混合层。

## 自测

1. GQA 与 MLA 各自压缩的是哪一份账？代价分别是什么？
2. 为什么 Attention Sink 会影响 KV 驱逐策略？
3. 说出 MoE 路由崩塌的成因和一个解法。

## 复习锚点

- 词表、位置、块内结构、替代路线，四层分开记。
- 省显存与省算力不是同一件事。
- 每个“新架构”都要问：它替换了哪个旧组件，代价落到谁身上。
