# 第 4 章：后训练与解码（48–70）

这一组分成两段：48–60 把基座变成“会按人类偏好回答”的模型；61–70 决定它在生成时怎样选 token。

## 一句话核心

后训练改的是“回答分布”，解码改的是“从分布里怎么取”。两者都会影响最终体验，但优化目标不同。

## 学习目标

- 能区分 SFT、RLHF、DPO、RLVR 各需要什么数据与反馈。
- 能解释奖励黑客、ORM/PRM、拒绝采样分别解决哪一段。
- 能按任务选 temperature、top-p、beam、best-of-n，而不是只调一个温度。

## 机制表

| # | 机制 | 一句话 | 代价或边界 |
|---|---|---|---|
| 48 | SFT 指令微调 | 用指令—回答对做监督学习，只对回答部分算损失 | 教格式与人格；知识主要来自预训练 |
| 49 | LoRA | 冻结原权重，旁挂两个低秩矩阵，只训它们 | 可训参数降到千分之一；推理可合并回原权重 |
| 50 | 奖励模型 | 给同一提示的两个回答标好坏，训一个标量打分器 | 奖励模型是人的替身，也是最脆弱的一环 |
| 51 | RLHF | 收集偏好 → 训奖励模型 → 用 PPO 优化策略，并用 KL 拴住 | 奖励模型偏差会被 PPO 放大 |
| 52 | RLAIF | 用 AI 按原则做偏好标注，替代人工 | 成本降一个数量级；把人的价值判断换成判分模型的偏见 |
| 53 | RLVR | 把答案交给验证器，可自动判对错的任务直接给奖励 | 不需要奖励模型；任务必须可验证 |
| 54 | DPO | 直接用偏好对算分类损失，省掉奖励模型与在线采样 | 失去在线探索能力；β 语义与 RLHF 相反 |
| 55 | 宪法式 AI | 先写原则，让模型自我批评修订，再用修订样本做偏好训练 | 省标注；原则漏洞没人兜 |
| 56 | 奖励黑客 | 优化器找到奖励模型的缝，把更长、更漂亮当成更好 | 不是模型学坏，是代理指标必然被挤 |
| 57 | 过程奖励与结果奖励 | ORM 只看最终答案，PRM 每一步都判 | PRM 能找到第几步错，标注贵十倍 |
| 58 | 拒绝采样微调 RFT | 同一题采多条，用验证器筛出正确解，再做 SFT | 不需要奖励模型和 RL；只抬高分布尾巴，不创造新能力 |
| 59 | RL 环境构造 | 单元测试、数学比对、SQL 执行、网页断言都是环境 | 能力上限常由“有没有可自动判分的环境”决定 |
| 60 | 多轮 RL 与信用分配 | 几十步任务最后才知道成败，要给每步算优势 | 做不好，模型只学会蒙对最后一步 |
| 61 | 采样策略 | temperature 调分布尖平，top-k/top-p/min-p 截候选 | 决定同一个模型的“性格”；参数互相作用 |
| 62 | 受限解码 | 把 JSON schema、正则、语法编译成状态机，只放合法 token | 保证可解析；过度约束会拉低质量 |
| 63 | 推测解码 | 小模型草拟 K 个 token，大模型一次前向验收 | 省的是带宽不是计算；接受率低会倒亏 |
| 64 | 思维链 | 让模型先写推理步骤，把中间结论写回上下文 | 用生成 token 当草稿纸；2026 年已是训练出来的行为 |
| 65 | 自洽性 | 同一题采样多条思维链，对最终答案投票 | 用算力换正确率；提升随采样数对数增长 |
| 66 | 上下文学习 | 把示例当临时训练集，注意力在前向里做近似优化 | 示例顺序会影响结果；不是微调 |
| 67 | beam search | 每步保留概率最高的 k 条路径，最后选总分最高 | 比贪心稳，但输出更“标准”、更不自然 |
| 68 | 重复惩罚 | 对已出现 token 降权，抑制复读 | 温度越低越容易复读；惩罚太狠伤流畅性 |
| 69 | best-of-n | 一次生成 n 个候选，用奖励模型或验证器挑最好 | 用算力换正确率；收益对数级 |
| 70 | 思维树 ToT | 把思维链展开成树，允许分叉、回溯、给中间步骤打分 | 每次分叉都要重新调用模型，成本高 |

## 选择顺序

先问任务有没有可验证答案：有就走 RLVR/RFT；没有就走偏好数据（RLHF/DPO）。再问要不要在线探索：要就 PPO，不要就 DPO。最后才调解码参数。

## 常见误解

- “DPO 一定比 RLHF 差。”它省掉在线探索，适合偏好固定、成本敏感的场景。
- “思维链是提示词技巧。”推理模型的思维链是强化学习训出来的行为。
- “推测解码是免费加速。”接受率低时它比不开还慢。

## 自测

1. RLHF、DPO、RLVR 各需要什么数据？
2. 奖励黑客为什么不是模型“学坏”？
3. 什么任务适合 best-of-n，什么任务不适合？

## 复习锚点

- 后训练：数据形态决定算法。
- 解码：温度、截断、草稿、搜索是四个不同旋钮。
- 可验证任务优先 RLVR，主观任务才用偏好模型。
