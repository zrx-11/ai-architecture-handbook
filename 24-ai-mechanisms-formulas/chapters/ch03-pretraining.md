# 第 3 章：预训练机制（22–47）

预训练不是“把数据喂进去”一件事，而是数据、目标、优化、并行、精度、稳定性六条流水线同时成立。任何一条崩了，loss 曲线都会告诉你。

## 一句话核心

预训练的每个机制都在回答两个问题：怎样让梯度有效，怎样让上千张卡不互相等。

## 学习目标

- 能区分数据去重、配比、课程与 mid-training 各在哪一步。
- 能解释 DP、TP、PP、EP、序列并行分别切什么、通信量在哪里。
- 能说出 loss spike、路由崩塌、显存爆掉各自的急救顺序。

## 机制表

| # | 机制 | 一句话 | 代价或边界 |
|---|---|---|---|
| 22 | 数据去重与配比 | 近似去重去掉重复段落，再按领域、质量、语言定比例 | 最不性感、收益最大；重复会放大记忆与偏见 |
| 23 | BERT 与 GPT 预训练目标 | BERT 挖空填空，GPT 预测下一个 token | 生成侧最终只剩下一 token 预测；掩码模型退到检索与嵌入 |
| 24 | 反向传播 | 前向算预测与损失，反向用链式法则逐层求梯度 | 一次反向约前向两倍；要存中间激活，显存随层数与 batch 涨 |
| 25 | 优化器 | SGD 看脚下，动量累速度，Adam 给每个参数自适应步长 | Adam 状态占显存；Muon 等新优化器在大规模上开始挑战 |
| 26 | 学习率调度 | 先线性预热，再余弦退火到接近零 | 预热让二阶矩先稳定；尾部退火常配高质量数据 |
| 27 | 权重初始化 | Xavier/Kaiming 让每层输出方差保持稳定 | 深模型残差分支还要乘 1/√(2N) 缩放 |
| 28 | 缩放定律 | loss 对参数、数据、算力在双对数坐标上近似直线 | 能预估“多花十倍算力买到多少”，但不预测具体能力 |
| 29 | 涌现与度量 | 换一种度量，连续提升会被压成突变 | “涌现”有一部分是离散指标造成的错觉 |
| 30 | 数据并行与张量并行 | DP 每卡一份参数算不同数据；TP 把权重矩阵切开 | DP 通信量等于参数量；TP 通信更重，通常只在机内 NVLink 做 |
| 31 | 流水线与专家并行 | PP 按层切，EP 把不同专家分到不同卡 | PP 有空泡；EP 有 all-to-all，专家越多通信越贵 |
| 32 | 序列并行 | 把长序列的序列维切开，注意力与 FFN 分别处理 | 长上下文训练的真正瓶颈常是激活，不是参数 |
| 33 | 通信与计算重叠 | 等梯度同步时顺手算下一批，让网络与算力同时跑 | 重叠做得好，千卡线性度能明显提高 |
| 34 | loss spike 与稳定性 | loss 突然飙升，多由梯度爆炸、logits 过大或脏数据触发 | 先梯度裁剪、降学习率、回滚检查点，再查数据 |
| 35 | MoE 路由崩塌 | 早期路由器偏爱少数专家，其余收不到梯度而废掉 | 负载均衡损失、容量限制、噪声注入都是解法 |
| 36 | 分位数均衡 | 不靠辅助损失，直接看打分分布反推调度偏好 | 专家数到几百后传统辅助损失难调，这是新解 |
| 37 | 梯度检查点 | 前向只存每 k 层激活，反向重算这一段 | 省激活不省参数；训练会慢两三成 |
| 38 | 混合精度 | 前向 bf16/fp16，主权重留 fp32，配损失缩放 | bf16 动态范围大、省心；纯 fp32 已不主流 |
| 39 | 量化感知训练 QAT | 训练时就模拟低精度舍入，反向用直通估计器 | 4bit 以下 PTQ 掉点明显时用；工程复杂度高 |
| 40 | ZeRO / FSDP | 把参数、梯度、优化器状态分片，用到哪片取哪片 | 优化器状态最占地方，先切它收益最大 |
| 41 | 算子融合 | 把 LayerNorm 四步、注意力 QK→softmax→V 合成一个 kernel | 省显存读写，端到端提速一到三成；中间结果只被下游用一次时才值得 |
| 42 | 知识蒸馏 | 学生同时学硬标签与教师软标签 | 温度常取 2–5；软标签含相似性信息 |
| 43 | 多教师在线蒸馏 MOPD | 多个领域专家在学生自己生成的轨迹上给密集奖励 | 解决“多个单点能力怎么合进一个模型”，不是简单灌一个更大教师 |
| 44 | 中期训练 mid-training | 预训练后、后训练前，用高质量长文档与领域数据再训一段 | 拉长上下文、加深代码与数学；直接上后训练会浪费底座 |
| 45 | 长上下文扩展训练 | 4K 训完，再用少量长文档逐步拉到 32K、128K | 全程长序列太贵；渐进扩展用少量算力拿大部分效果 |
| 46 | 断点续训 | 参数、优化器状态、数据位置、随机数状态都要存 | 千卡训练一天崩一次是常态，续训决定有效算力 |
| 47 | 多 token 预测 MTP | 一次预测未来 2–4 个 token，每个位置配轻量头 | 训练时学会往后看；这些头还能当投机解码草稿 |

## 训练账本顺序

先算显存（参数、梯度、优化器、激活），再算 FLOPs，再算通信，最后才算时间。顺序反过来，很容易得出“单卡能跑 70B”的假结论。

## 常见误解

- “数据并行加卡就能装下更大模型。”DP 只分摊数据，每卡仍有一份完整权重。
- “bf16 一定比 fp16 快。”要看硬件与数值范围；bf16 更省心，不是所有算子都更快。
- “路由崩塌靠调大辅助损失就行。”专家越多，辅助损失越难调，分位数均衡是另一种思路。

## 自测

1. DP、TP、PP、EP 各切什么？通信量最大的是哪个？
2. 为什么长上下文训练先爆的是激活，不是权重？
3. loss spike 的急救顺序是什么？

## 复习锚点

- 数据 → 目标 → 反向 → 优化 → 并行 → 稳定。
- 显存四件套：参数、梯度、优化器状态、激活。
- 并行策略由互联带宽决定，不由“卡数”决定。
