# 第 3 章：数据工程：清洗、去重、配比与 packing

- **难度**：★★☆ | **预估学时**：1.5 小时 | **前置**：第 2 章

## 学习目标

1. 列出预训练数据的五道过滤；
2. 解释为什么重复数据会让模型“背答案”；
3. 画出 packing 后的一条训练样本，标出 loss mask。

## 一句话核心

模型的能力上限，很大一部分在数据管线里已经决定了；训练代码只是把数据里的规律压进参数。

## 3.1 五道过滤

| 步骤 | 目的 | 最小做法 |
|---|---|---|
| 质量过滤 | 去掉广告、乱码、模板垃圾 | 语言识别、长度、符号比例、重复行 |
| 去重 | 减少记忆与浪费 | 精确哈希 + MinHash/SimHash 近似去重 |
| 隐私清洗 | 去掉身份证、手机号、密钥 | 正则 + PII 分类器 + 人工抽检 |
| 污染检查 | 防止评测题泄漏 | 与评测集做 n-gram/embedding 相似度比对 |
| 配比 | 控制代码、中文、英文、数学比例 | 先小规模消融，再定采样权重 |

去重不是“可选项”。同一段文本重复 100 次，模型会把它当成高置信事实；评测时看起来会，换一个问法就露馅。

## 3.2 从文档到 token

一条流水线通常是：

```text
原始文件 → 解析 → 语言识别 → 质量分 → 去重 → PII → tokenizer → 分片 → packing
```

tokenizer 之后要统计 token 数，不要用文件大小。一个 1GB 的 JSONL 可能只有 0.3B token，也可能有 1B token，取决于语言和格式。

## 3.3 packing 是什么

语言模型训练希望每个 batch 都是固定长度 `T`。把多条短样本拼成一条长序列，叫 packing：

```text
[样本A 20 tokens][样本B 30 tokens][样本C 50 tokens] → 一条 100 tokens
```

问题：A 的最后一个 token 不能预测 B 的第一个 token。解决方法是 `attention mask` 分块，或在每条样本之间插入 `eos` 并重置位置。只拼不隔离，模型会学到跨文档的假连接。

## 3.4 SFT 数据的特殊之处

预训练只要“下一个 token”；SFT 要区分“用户说的”和“助手说的”。常见做法：

- 用聊天模板把多轮对话拼成一条；
- 只对助手回复计算 loss，用户 token 的 label 设为 `-100`；
- 保留系统提示，但不要让它抢走太多训练信号；
- 检查空回复、截断、角色错位和重复回答。

## 检查点

- 给一条 3 文档拼接样本，画出哪些位置需要 mask。
- 解释“去重”和“去污染”的区别：它们防的不是同一件事。
- 用 tokenizer 统计你手头一段中文的 tokens/字符，给出一个训练 token 预算。
