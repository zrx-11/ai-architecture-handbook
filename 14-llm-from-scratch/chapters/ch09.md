# 第 9 章：LoRA 与 QLoRA：用低秩适配改行为

- **难度**：★★★ | **预估学时**：2 小时 | **前置**：第 8 章

## 学习目标

1. 写出 LoRA 的低秩分解与参数量；
2. 解释 rank、alpha、target modules 的影响；
3. 说清 QLoRA 省的是哪部分显存，以及它的代价。

## 一句话核心

LoRA 不重写整个权重，而是学一个低秩“补丁”：`W + BA`。它把可训练参数从 `d×d` 降到 `d×r + r×d`。

## 9.1 低秩分解

原权重 `W` 形状 `[d_out, d_in]`，冻结。LoRA 加：

$$
W' = W + \frac{\alpha}{r}BA
$$

`B` 是 `[d_out, r]`，`A` 是 `[r, d_in]`，`r << d`。可训练参数 `r(d_out+d_in)`。例：`d=4096, r=8`，原矩阵 16.7M，LoRA 只有 65k 左右（单侧）。

初始化通常 `A` 随机、`B` 为零，使训练开始时补丁为 0，不破坏原模型。

## 9.2 rank 与 alpha

- `r` 太小：容量不够，学不动复杂行为。
- `r` 太大：参数变多，接近全量微调，失去 LoRA 的意义。
- `alpha` 控制补丁强度；常见 `alpha=2r` 或固定 16/32，但这不是定律。
- target modules 决定加在哪些线性层：只加 Q/V 常见；加所有线性层容量更大，显存也更高。

## 9.3 QLoRA

QLoRA 把冻结的 base 权重量化成 4-bit（NF4），在前向/反向时反量化，LoRA 补丁仍用较高精度训练。省的是“base 权重显存”，不是“激活显存”。序列长、batch 大时，激活仍可能爆。

代价：量化/反量化带来速度开销；4-bit 不是免费午餐，校准和实现质量会影响稳定性。

## 9.4 合并与部署

训练完可以把 `BA` 合并回 `W`，得到一个普通 checkpoint，推理时没有 LoRA 额外开销。也可以保留 adapter，热切换多个任务；但多 adapter 的服务调度更复杂。

## 检查点

- 解释 `B=0` 初始化为什么重要。
- 说出 QLoRA 能省什么、不能省什么。
