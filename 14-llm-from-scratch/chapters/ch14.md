# 第 14 章：最小可复现路线：从 CPU 到单卡

- **难度**：★★☆ | **预估学时**：1.5 小时 | **前置**：第 1–13 章

## 学习目标

1. 按硬件选一条可完成的项目路线；
2. 写出一个“可验收”的训练/部署清单；
3. 知道哪些开源项目该读、该跑、只该看。

## 一句话核心

不要一上来追 7B。先用最小模型把 tokenizer、attention、loss、SFT、KV 五件事跑通，再放大规模；每步都有可检查的产物。

## 14.1 三条路线

### A. CPU 半天：只验证机制

- 字符级 tokenizer，训练一个 2 层、`d=64` 的 causal Transformer。
- 语料：几百 KB 中文/英文文本。
- 验收：loss 从随机水平下降；能生成连贯的短句；手算 attention 与代码输出一致。
- 不追求效果，追求“每个形状对”。

### B. 单卡 1–2 天：tiny LLM 全链路

- 10M–60M 参数，BPE 词表 4k–8k。
- 预训练 0.1B–1B token；SFT 1k–5k 条；LoRA rank 8–16。
- 验收：base 会续写，SFT 会按模板答，LoRA 能改风格；保存 checkpoint、日志、样本。
- 参考：MiniMind 的 64M 路线、Modern LLM Notebook 的 64M 实验。

### C. 云上 1 周：小模型对齐 + 服务

- 1B 以下模型，SFT + DPO/GRPO 小实验。
- 用 vLLM/TGI 之类做服务，测首 token 延迟、吞吐、KV 占用。
- 验收：一张表说明模型、数据、硬件、延迟、成本、失败案例。
- 参考：`smol-course` 的对齐单元、`22-serving-deep` 的服务账本。

## 14.2 项目产物清单

```text
data/        数据卡：来源、许可、清洗规则、token 数
tokenizer/   merges、vocab、特殊 token、编码样例
train/       配置、日志、loss 曲线、随机种子
checkpoints/ base / sft / lora / merged
eval/        题集版本、指标、失败样本、污染检查
serve/       启动命令、并发配置、延迟/成本表
README       复现步骤与已知限制
```

没有数据卡和评估记录的训练，不算完成。

## 14.3 读开源项目的正确姿势

- **跑**：MiniMind（Apache-2.0）、smol-course（Apache-2.0）这类许可清楚、能本地跑的最小链路。
- **读**：LLMs-from-scratch（7 章结构）、Modern LLM Notebook（23 个 notebook）、Happy-LLM（中文 8 章）。
- **看演示**：Transformer Explainer、AnimatedLLM、LLM Visualization 用来建立直觉，不替代手算。
- **不要整段复制**：CC-BY-NC-SA 的教程可以读，但商用/再分发要看清许可；fast.ai 的 prose 有额外限制。

## 检查点

- 选一条路线，写出你的模型规模、数据量、硬件和验收指标。
- 给项目建一个 `README` 目录树，标出哪一项最容易缺。
- 说出一个“只该看、不该跑”的项目及原因。

## 结课标准

你能向别人解释：这个模型为什么能生成下一个 token、SFT 改了它什么、KV 为什么占显存、评测分数为什么不能直接信。能解释，比能跑一个 demo 更重要。
