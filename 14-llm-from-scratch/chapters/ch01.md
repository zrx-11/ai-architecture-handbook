# 第 1 章：一次 LLM 训练到底包含什么

- **难度**：★☆☆ | **预估学时**：1 小时 | **前置**：会跑 Python，知道梯度是什么

## 学习目标

学完本章，你能：

1. 画出预训练、SFT、偏好对齐、评测、推理服务五段流水线；
2. 说清每段需要什么数据、产出什么文件、用哪类指标验收；
3. 按自己的硬件选“最小实验”而不是一上来训练 7B。

## 一句话核心

LLM 不是“训练一次”就结束，它是一条流水线：每段都改变模型的行为，也都有自己的失败方式。

## 1.1 五段流水线

| 阶段 | 输入 | 模型在学什么 | 典型产出 |
|---|---|---|---|
| 预训练 Pretrain | 海量无标注文本 | 下一个 token 的概率 | base checkpoint |
| 监督微调 SFT | 指令-回答对 | 按对话格式回答 | instruct checkpoint |
| 偏好对齐 | chosen / rejected 对 | 哪种回答更被偏好 | aligned checkpoint |
| 评测 Eval | 固定题集与真实流量 | 不是“学”，是测量 | 报告与失败样本 |
| 推理服务 Serve | 用户请求 | 不是“学”，是调度 | API、延迟、成本 |

预训练像“读万卷书”，SFT 像“学答题格式”，偏好对齐像“纠正偏好”，评测是“考试”，服务是“开门营业”。把它们混成一步，是很多教程最大的误导。

## 1.2 每段的验收物

- 预训练：验证集 loss 曲线、token 吞吐、显存峰值、可复现的 checkpoint。
- SFT：格式遵循率、任务准确率、拒答边界；不能只看训练 loss。
- 偏好对齐：偏好胜率、长度偏差、KL 距离；不能只看奖励分数。
- 评测：固定版本题集、污染检查、人工抽检；不能只跑一个排行榜。
- 服务：首 token 延迟、吞吐、KV 占用、单位成本；不能只看单条 demo。

## 1.3 三条现实路线

| 路线 | 规模 | 适合谁 | 能验证什么 |
|---|---|---|---|
| CPU 最小实验 | 字符级或 1M 参数 | 零基础 | tokenizer、attention、loss 是否真的会动 |
| 单卡小模型 | 10M–100M | 有 GPU 或云卡 | 预训练→SFT→LoRA 全链路 |
| 多卡/云 | 1B 以上 | 团队 | 并行、吞吐、服务与成本 |

本手册默认你走前两条。大模型不是必须自己训练才能理解；先用小模型把每个形状和损失跑通，再读 DeepSeek 的架构，效率更高。

## 1.4 一张形状账本

后面每章都会记一行：

```text
batch B, 序列 T, 隐藏维 d, 层数 L, 头数 H, 词表 V
输入 ids:        [B, T]
token embedding: [B, T, d]
attention 分数:  [B, H, T, T]
FFN 中间维:      [B, T, 4d]（具体倍数看模型）
logits:          [B, T, V]
```

把这五行的形状真正写对，比背“Transformer 有 encoder 和 decoder”有用得多。

## 检查点

- 不看笔记，画出五段流水线，并写出每段的一个失败模式。
- 用自己的话解释：为什么 SFT 后的模型不一定比 base 模型“知识更多”？
- 选一条路线，写下你机器上的显存、内存和可接受训练时长。
