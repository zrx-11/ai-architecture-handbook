# 第 8 章：SFT：让基座模型学会对话

- **难度**：★★★ | **预估学时**：2 小时 | **前置**：第 7 章

## 学习目标

1. 写出一个聊天模板，并标出哪些 token 参与 loss；
2. 解释 `loss mask`、packing、多轮对话的相互作用；
3. 识别 SFT 过拟合和格式污染。

## 一句话核心

SFT 不是“教模型新知识”，主要是教它“按什么格式、什么角色、什么边界回答”；知识主要来自预训练。

## 8.1 一条训练样本

```text
<system>你是助手</system>
<user>把这句话翻译成英文：今天下雨</user>
<assistant>It is raining today.</assistant>
```

模板把角色标记、换行、结束符都变成 token。模型在 `<assistant>` 之后的位置学习预测回答 token；用户和系统部分的 label 设为 `-100`，不计算 loss。否则模型会学“复述用户问题”，而不是“回答”。

## 8.2 多轮对话

多轮样本要保留历史，但通常只对每一轮助手回复算 loss。不要把整段对话都算 loss；也不要把不同轮次用错误的分隔符拼在一起。轮次边界、角色标记、结束符必须和推理时完全一致。

## 8.3 packing 与 mask

SFT 样本长度差异大，常把多条样本 pack 到 `T`。必须保证：

- 每条样本内部 causal mask 正常；
- 样本之间不能互相看见（block-diagonal mask 或重置位置）；
- padding 和 prompt 的 label 都是 `-100`；
- 结束符 `eos` 要保留，否则模型学不会停。

## 8.4 数据量与质量

小模型 SFT 常见 1k–100k 条。质量比数量重要：指令清晰、回答准确、格式统一、覆盖失败模式。要主动加入“不知道”“需要更多信息”“拒绝不安全请求”的样本，否则模型会过度自信。

## 8.5 过拟合与灾难性遗忘

- 训练 loss 很低但验证集差：过拟合或模板泄漏。
- 回答变短、变机械：数据风格单一。
- 通用能力下降：SFT 数据太窄或学习率太大。
- 只会一种模板：推理模板与训练不一致。

对策：混入少量预训练数据、做指令多样性、早停、保留 base checkpoint、用 held-out 指令集评估。

## 检查点

- 解释为什么 SFT 后模型可能“更会答”但“知识没有增加”。
- 给出三个 SFT 数据质量检查项。
