# 第 4 章：Embedding 与位置编码：给 token 一个坐标

- **难度**：★★☆ | **预估学时**：1.5 小时 | **前置**：第 2 章

## 学习目标

1. 解释 one-hot、embedding、weight tying 之间的关系；
2. 手算正弦位置编码的一个维度；
3. 说清 RoPE 为什么能让模型感知相对位置。

## 一句话核心

Embedding 把离散 id 变成可微向量；位置编码把“顺序”注入这个向量，否则 Transformer 对词序几乎无感。

## 4.1 从 one-hot 到 embedding

词表大小 `V=10000`，隐藏维 `d=512`。one-hot 是 `[10000]`，只有一个 1；embedding 是一个 `[10000, 512]` 的矩阵，取第 `id` 行，得到 `[512]`。

参数量：`10000 × 512 = 5.12M`。如果输出层和输入 embedding 共享同一个矩阵，叫 weight tying，可省一份参数，也能让输入输出空间更一致；不是所有模型都这么做。

## 4.2 正弦位置编码

对位置 `pos`、维度 `i`：

$$
PE(pos,2i)=\sin\left(\frac{pos}{10000^{2i/d}}\right),\quad
PE(pos,2i+1)=\cos\left(\frac{pos}{10000^{2i/d}}\right)
$$

直觉：不同维度有不同的波长，像一组不同刻度的尺子。模型可以通过线性组合判断相对位移。它的缺点是对超出训练长度的外推不自然。

## 4.3 RoPE：旋转 query 和 key

RoPE 不把位置加到 token 向量上，而是把 query/key 的二维子空间按位置旋转。两个 token 的注意力分数只依赖它们的相对距离：

```text
q_m = R_m q,  k_n = R_n k
q_m^T k_n = q^T R_{n-m} k
```

因此模型学到的是“相对位置”而不是“绝对第几个”。长上下文外推、YaRN 之类的方法，都是在改旋转频率或插值策略，不是简单“把长度改大”。

## 4.4 形状账本

```text
ids:             [B, T]
token embedding: [B, T, d]
position:        [B, T, d] 或旋转作用在 q/k 上
输入 Transformer: [B, T, d]
```

注意：位置编码的参数量通常很小，但它对长上下文行为的影响很大。不要把“支持 128K”当成“128K 内都一样好”。

## 检查点

- 手算 `PE(1,0)` 和 `PE(1,1)`，说明它们为什么是一组 sin/cos。
- 用自己的话解释 RoPE 的分数为什么只依赖相对位置。
- 列出至少两个“长上下文变长但效果变差”的原因。
