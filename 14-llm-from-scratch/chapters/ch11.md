# 第 11 章：推理：KV cache、解码与量化

- **难度**：★★★★ | **预估学时**：2 小时 | **前置**：第 6、7 章

## 学习目标

1. 区分 prefill 和 decode；
2. 算一个模型的 KV cache 大小；
3. 解释 temperature、top-k、top-p、量化、投机解码各自改变什么。

## 一句话核心

推理的瓶颈通常不是“算不动”，而是“显存带宽和 KV 太大”；解码是一个 token 一个 token 地搬权重。

## 11.1 prefill 与 decode

- prefill：把整段 prompt 并行送进模型，计算量大，能充分利用 GPU。
- decode：每次只生成一个 token，必须读全部权重和 KV，通常是 memory-bound。

首 token 延迟看 prefill，吞吐看 decode，长上下文看 KV。三者要分开测。

## 11.2 KV cache 公式

$$
\text{KV bytes}=2 \times L \times H_{kv} \times d_{head} \times T \times B \times \text{bytes}
$$

`2` 是 K 和 V；`L` 层数；`H_kv` KV 头数；`d_head` 每头维度；`T` 序列长度；`B` 并发序列；`bytes` 每元素字节（FP16=2）。

例：`L=32, H_kv=8, d_head=128, T=8192, B=1, FP16`：

```text
2 * 32 * 8 * 128 * 8192 * 2 ≈ 1.07 GB
```

这只是一条序列。并发 32 条就是 34GB，已经吃掉一张卡。GQA/MQA 降低 `H_kv`，PagedAttention 减少碎片，都是在打这个账。

## 11.3 解码策略

- greedy：确定性，容易重复。
- temperature：软化/锐化分布；`T→0` 接近 greedy。
- top-k：只从概率最高的 k 个采样。
- top-p：从累积概率达到 p 的最小集合采样。
- repetition penalty：压重复，但可能破坏专有名词。

## 11.4 量化与投机解码

量化把权重/激活变窄，减少显存和带宽；decode 阶段收益通常更明显，prefill 阶段要看算力。投机解码用小模型草拟多个 token，大模型并行验证，能在不改变分布的情况下提速，但依赖草稿模型的质量。

## 检查点

- 算 `L=40, H_kv=8, d_head=128, T=32768, B=8, FP16` 的 KV 大小。
- 解释为什么 decode 是 memory-bound。
- 说出量化的两个代价和一个收益。
