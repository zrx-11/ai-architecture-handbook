# 训练与部署故障排查模式

## 1. 先用形状定位，再怀疑算法

现象：报错 `shape mismatch`、loss 不降、生成乱码。

顺序：

1. 打印 `ids / logits / labels` 的形状；
2. 打印 tokenizer 解码后的原文，确认输入没有错位；
3. 用单 batch 过拟合，看 loss 能否接近 0；
4. 再查 mask、位置编码、label shift。

单 batch 都过拟合不了，先不要调超参。

## 2. loss 不降的四类原因

| 现象 | 先查 |
|---|---|
| 一开始就 NaN | 学习率、fp16 溢出、坏数据 |
| loss 平在高位 | label 错位、mask 全 0、学习率太小 |
| loss 降但生成乱 | 数据重复、模板错、评测泄漏 |
| 训练降验证升 | 过拟合、数据分布不一致 |

## 3. 显存账本

按顺序算：

```text
参数 + 梯度 + 优化器状态 + 激活 + KV + 临时区
```

先降 batch/序列长度，再考虑梯度累积、ZeRO、量化、LoRA。不要一上来开最复杂的并行。

## 4. RAG 失败定位

- 召回为空：查分词、索引、过滤条件；
- 召回相关但答错：查重排、上下文拼接、模型是否忽略证据；
- 引用错：查 chunk id 与生成引用是否对齐；
- 答案过时：查索引版本和数据时间。

## 5. Agent 失败定位

先看轨迹：观察→思考→工具参数→工具结果→下一步。多数错误不是“模型笨”，是工具 schema 不清、返回格式不稳定、权限过大或没有停止条件。
