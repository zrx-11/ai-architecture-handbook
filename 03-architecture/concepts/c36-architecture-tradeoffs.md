# 架构取舍

- **难度**：进阶 | **涉及章节**：第 10–13 章

## 一句话定义

架构取舍是在给定负载、成本和质量约束下，选择“哪笔账可以省、哪笔账不能省”的决策过程。

## 为什么重要

每个架构组件都有代价。看懂取舍，才能在选型和评审时不迷信“最新”“最大”“压缩率最高”。

## 详解

常见取舍：

| 选择 | 省什么 | 付出什么 | 适合 |
|---|---|---|---|
| MoE | 单 token 计算 | 显存、通信、路由不稳 | 参数要大、算力受限 |
| MLA | KV cache | 计算图复杂 | 长上下文、显存紧张 |
| CSA/HCA | 注意力 FLOPs + KV | 索引器、精度损失 | 1M 上下文 |
| CED | prefill 计算 | 编码器表达受压、工程复杂 | 输入密集 |
| mHC | 训练稳定性 | 激活/通信开销 | 超深模型 |
| Muon | 收敛速度/稳定性 | ZeRO 复杂 | 大规模预训练 |
| Engram | 矩阵计算 | 存储、带宽 | 记忆密集型任务 |
| FP4 | 存储/带宽 | 精度风险 | 成本敏感推理 |

决策规则：
1. 先量化瓶颈，不凭感觉。
2. 只选“能解决当前瓶颈”的机制，不为用不上的能力付费。
3. 给精度损失留验证计划。
4. 算总成本，不算单项指标。

## 常见误解

- 压缩率越高不一定越好，精度和工程复杂度要一起算。
- 参数越大不一定越强，数据和架构效率同样重要。
- 最新一代不一定适合所有负载，V4.1-Flash 也不全面超过 V4-Pro。
