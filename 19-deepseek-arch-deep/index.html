00课程概览：把 DeepSeek 的结构件串成一条线

这门课只讲架构，不重复论文里的实验表格。主线是：dense → DeepSeekMoE → MLA → MTP → DSA → V4 的 CSA/HCA → V4.1 的 CED/CSA2/Engram/DSpark。每一节都回答两个问题：解决什么瓶颈，代价是什么。

学完你能做到

  • 用参数量、激活参数、KV cache 三个数字描述一代模型。
  • 说清 MoE 的路由、共享专家、负载均衡各自解决什么问题。
  • 手算 MLA 每 token 每层缓存多少字节，以及 128K 上下文的总账。
  • 解释 DSA、CSA、HCA、CED 分别在压缩什么。
前置：知道注意力、FFN、KV cache、softmax。没读过论文也能跟，但建议先看 `02-paper-teardown` 和 `03-architecture` 的对应章节。

01家族时间线与三代骨架

先把代际和结构件对齐。不要背模型名，先记每一代解决了什么瓶颈。

代际总参数 / 激活层数路由专家top-k上下文核心结构件
V3671B / 37B61256 + 1 共享8128KMLA、DeepSeekMoE、MTP
V4-Pro约 1.6T / 49B61384 + 1 共享61MCSA、HCA、mHC、Muon、FP4
V4-Flash284B / 13B43256 + 1 共享61M同上，规模缩小
V4.1-Flash552B 主干 + 196B Engram40384 + 1 共享61MCED、CSA2、Engram、DSpark

V3 的关键是“用 MoE 把总参数做大，用 MLA 把 KV cache 压小”。V4 的关键是“在 1M 上下文下，把注意力和缓存再压一层”。V4.1 的关键是“非对称压缩 + 外部记忆”。

“总参数”不等于“每个 token 都算”。MoE 只激活 top-k 个专家，激活参数远小于总参数。看到 1.6T 先问激活是多少。

02MoE：把 FFN 拆成专家

Transformer 每层有两个大块：注意力 + FFN。FFN 通常占参数的大头。MoE 把一个大 FFN 拆成很多小专家，每个 token 只走其中几个。

$$y=\sum_{i\in\text{top-}k}g_iE_i(x)$$

$E_i$ 是第 i 个专家，$g_i$ 是路由权重。V3 有 256 个路由专家 + 1 个共享专家，top-8。

三个设计点

  • 细粒度专家：专家多而小，组合更灵活。
  • 共享专家：每个 token 都过一个共享专家，兜住通用知识，减少路由专家之间的重复。
  • 负载均衡：如果所有 token 都挤向少数专家，其他专家白占显存。训练时加辅助损失，逼路由分散。

参数量账

假设每个专家参数量 $P_e$，路由专家 $N$ 个，共享专家 1 个：总 FFN 参数约 $(N+1)P_e$，每 token 激活约 $(k+1)P_e$。V3 的 37B 激活里，大部分不是全部专家。

MoE 省的是“每 token 的计算”，不是“显存”。总参数仍要装进显存/内存，所以 MoE 模型通常需要多卡或大内存。

03MLA：把 KV cache 压小

标准多头注意力要缓存每个 token 的 K 和 V。层数越多、头越多、上下文越长，缓存越爆。

V3 的 MLA 不直接缓存完整 K/V，而是缓存一个低秩潜向量，再投影出 K/V。论文口径下，每 token 每层缓存 512 + 64 = 576 个数。

$$\text{每 token 每层字节}=576\times2=1152\ \text{B（BF16）}$$

128K 上下文、61 层、单序列：

$$128000\times61\times1152\approx9.21\ \text{GB}$$

如果不压缩，同样配置下缓存会大得多。MLA 的代价是多了投影矩阵和计算，但省下的是显存和带宽。

576 这个数不是“所有头加起来 576 维”，而是论文里每 token 每层的缓存元素数。不同实现可能有布局差异，算账时以 config 和代码为准。

04MTP：一次预测多个 token

标准语言模型一次只预测下一个 token。MTP（多 token 预测）让模型在一次前向里预测未来多个 token，训练信号更密，也表示规划能力。

DeepSeek 的 MTP 不是简单加几个独立输出头，而是让第 $k$ 个预测头看前面已经预测出的 token 表示，形成链式依赖。

$$p(x_{t+1},x_{t+2}\mid x_{\le t})=p(x_{t+1}\mid x_{\le t})\cdot p(x_{t+2}\mid x_{\le t},x_{t+1})$$

推理时怎么用

MTP 头可以拿来做投机解码：先草拟多个 token，再用主模型验证。验证通过就一次接受多个，提升吞吐。不是所有部署都会开，取决于实现和负载。

MTP 增加训练计算和显存。它的收益主要在训练信号和推理加速，不是“白送”。

05DSA：稀疏注意力

全注意力每个 token 要看前面所有 token。1M 上下文、单序列的注意力配对数约：

$$10^6\times10^6=10^{12}$$

DSA 只选 top-k 个最相关的历史 token 参与注意力。论文口径 top-k=2048：

$$10^6\times2048\approx2.048\times10^9$$

两者相差约 488 倍。这就是“百万上下文能不能跑”的关键。

怎么选 top-k

需要一个轻量的打分器，快速估计每个历史 token 的相关性，再取前 k 个。打分器不能太重，否则省下的注意力又被它吃掉。

稀疏注意力不是免费的：选错 token 会丢信息；top-k 太小，长文档问答会漏关键段落。k 是精度和成本的旋钮。

06CSA：压缩稀疏注意力

V4 的 CSA 在 DSA 的基础上再压一层：先把历史 token 的 KV 压成块级表示，再在块上做稀疏选择。这样打分和注意力的对象都变少。

直观理解：DSA 是“在 token 级别挑 top-k”，CSA 是“先把 token 分块压缩，再在块级别挑 top-k”。块内信息被池化，块间用稀疏注意力。

代价

  • 压缩会丢细粒度信息，块太小省不了，块太大丢细节。
  • 块级选择可能漏掉块内的关键 token。
  • 实现复杂，训练和推理的 kernel 要配套。
CSA 的收益在长上下文：把“看所有 token”变成“看少量块”，计算和缓存一起降。短上下文时收益不明显。

07HCA：混合压缩注意力

HCA 把不同粒度的注意力混在一起：一部分头/层做局部精细注意力，一部分做块级压缩注意力。局部头保住细节，压缩头管长程。

这解决的是“全压缩丢细节、全精细太贵”的两难。混合的比例是设计参数，按任务和上下文长度调。

结构看什么适合
局部注意力近处 token语法、局部指代
压缩/稀疏注意力远处块长文档、全局主题
HCA两者混合既要细节又要长程
“混合”不是把所有机制简单相加。头数、层数、路由和缓存布局都要一起设计，否则省下的算力会被额外分支吃回去。

08mHC 与 Muon

mHC 可以理解为“多头超连接”一类的结构件，目标是让信息在层间走多条路径，改善深层训练的信号传播。具体实现论文有定义，课程里不逐行复刻 kernel。

Muon 是优化器方向的改动，核心是对动量矩阵做正交化/归一化，让更新方向更稳。它不等于“又一个 Adam 变体”，而是改更新矩阵的几何性质。

为什么架构课要讲优化器

同一副骨架，换优化器和初始化，训练稳定性和最终效果会差很多。DeepSeek 的技术报告把结构件和训练技巧放在一起讲，是有原因的。

mHC 和 Muon 的细节在论文里没有全部展开到 kernel 级。看到二手解读里给出“精确公式”时，先回去核对原文，别把推测当事实。

09Engram 与 DSpark

Engram 是 V4.1 引入的外部记忆/查表结构。它把一部分知识从“参数里算出来”变成“按索引查出来”，主干参数不必把所有事实都背进去。

V4.1-Flash 的口径是 552B 主干 + 196B Engram，总参数约 763B，但 prefill 激活 8B、decode 激活 16B。注意 prefill 和 decode 的激活不一样，因为两者计算模式不同。

DSpark 是 V4.1 的推理/稀疏化相关结构件，目标是进一步降低长上下文解码的成本。论文里对它的公开细节有限，课程里只讲它解决的问题，不编造实现。

Engram 的“查表”不是普通 embedding 查找。它和主干的交互、路由、训练目标都需要设计，不能简单理解成“外挂一个知识库”。

10V4.1 的 CED 与 CSA2

V4.1 的核心叙事是“非对称压缩”：prefill 和 decode 的瓶颈不同，不用同一套压缩策略。

  • Prefill：一次处理整段 prompt，计算密集，重点是吞吐。
  • Decode：一次生成一个 token，访存密集，重点是 KV cache 带宽。

CED 可以理解为面向 decode 的缓存压缩/驱逐策略：把不重要的 KV 压掉或赶出快速缓存，保住关键 token。CSA2 是 CSA 的迭代版，进一步优化块级选择。

V4.1-Flash 的全局 KV 账约 890 B/token，相比 V3 的 1152 B/token 又降了一截。1M 上下文下单序列缓存仍然是 GB 级，不是“压到零”。

$$10^6\times890\approx0.89\ \text{GB（单序列，未计层数细节的口径换算）}$$

具体总账要乘层数、头数等布局参数，课程里给的是量级，不是部署报价。

11选型与成本

选型不要只看参数量。按顺序问五个问题：

  1. 任务需不需要 1M 上下文？不需要就别为长上下文付缓存钱。
  2. 延迟敏感还是吞吐敏感？decode 重访存，prefill 重算力。
  3. 显存能装下总参数吗？MoE 总参数大，激活小，但权重仍要装。
  4. 能不能用量化？FP8/FP4 省显存，但精度和 kernel 支持要验证。
  5. 许可证和数据合规能不能接受？
场景倾向理由
长文档问答、代码库级上下文V4/V4.1 长上下文档DSA/CSA/CED 省 KV
高并发短对话V4-Flash / V3 类小激活激活小，decode 便宜
离线批量生成大模型 + 高吞吐并行prefill 吞吐优先
单卡/边缘dense 小模型或蒸馏版MoE 权重装不下
架构选型的本质是“把瓶颈放在便宜的资源上”。长上下文把瓶颈推给 KV cache，MoE 把瓶颈推给显存和路由，CSA 把瓶颈推给压缩质量。

12常见误解与自测

五个误解

  • “MoE 总参数大，所以推理一定慢”：每 token 只激活 top-k，算力不一定大；但权重显存大。
  • “MLA 把 KV cache 压没了”：只是压到 576 个数/ token/层，仍有 GB 级开销。
  • “DSA 的 top-k 越大越好”：越大越准，也越贵；k 是精度—成本旋钮。
  • “V4.1 只是 V4 加参数”：它改的是压缩策略和记忆结构，不是单纯放大。
  • “论文没写 = 不存在”：论文没展开的实现细节，不能靠二手解读补成事实。
