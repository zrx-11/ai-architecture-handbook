## 🔬 CSA 的第一性原理推导：4 倍压缩 + top-k，到底省了多少

### 第一步：先算不压缩的账

标准注意力里，每个 query 要和前面所有 token 的 K 做点积。序列长度 $n$ 时，点积次数约为 $n^2/2$（因果注意力只算左半边）。$n=1{,}000{,}000$ 时，约 $5\times10^{11}$ 次点积，单次点积还要乘维度，计算量爆炸。

KV cache 也不小：每 token 64 KB，1M token 就是 64 GB。

### 第二步：压缩 4 倍，候选降到 25 万

CSA 把每 4 个 token 的 KV 压成 1 条。压缩不是平均，而是用权重加权：

$$C_i^{\text{Comp}}=\sum_{j=4i}^{4i+3}S_j\odot C_j$$

$S_j$ 是 4 个压缩权重，经过 softmax 归一化，加起来为 1。$C_j$ 是原始 KV 条目。这样序列长度从 $n$ 变成 $n/4$。

$n=1M$ 时，候选从 100 万降到 25 万。只做这一步，注意力计算量降到约 1/16（因为 $n^2$ 变小 16 倍），KV cache 降到 1/4。

### 第三步：再稀疏选 top-k，候选降到 512

25 万条还是太多。CSA 用轻量索引器给每条候选打分，只选 top-k 条。V4-Flash 选 512 条，V4-Pro 选 1024 条。

这一步把核心注意力的候选从 25 万降到 512，计算量再降约 488 倍。压缩和稀疏是乘法关系：

$$\text{总降幅}\approx 4\times\frac{250{,}000}{512}\approx 1953\ \text{倍}$$

当然，实际不会这么夸张，因为索引器本身也要算分，局部 SWA 还要保留 128 条。但量级方向是对的。

### 第四步：压缩权重怎么来的

对每个 token 的 hidden state $h_j$，用一个矩阵 $W^Z$ 算出压缩分数 $z_j$，加上可学习位置偏置 $B$，在 4 个 token 内做 softmax：

$$S_j=\frac{e^{z_j+B_j}}{\sum_{l=4i}^{4i+3}e^{z_l+B_l}}$$

位置偏置让模型可以学“这 4 个 token 里哪个更重要”。比如压缩一个短语时，中心词权重可能更高。

### 第五步：为什么还要局部 SWA

压缩块内的 token 互相看不见。比如第 4 个 token 和第 1 个 token 在同一个压缩块里，压缩后只留一条表示，第 4 个 token 看不到第 1 个的细节。语言模型对最近几个 token 的依赖很强，所以 CSA 额外保留最近 128 个 token 的未压缩 KV，单独算一条局部注意力。

最终每个 query 的注意力来源：
- top-k 条压缩 KV（512 或 1024）
- 最近 128 条未压缩 KV

两者拼在一起做 softmax。

### 第六步：数值感受

1M token，4:1 压缩后 25 万条，选 top-512。每个 query 的核心注意力只算 512 + 128 = 640 条，而不是 100 万条。KV cache 只存压缩条目和最近窗口，不存全部历史。

### 差生检查

- $n$、$m$、$k$ 第一次出现都给了含义。
- 压缩公式和 softmax 权重逐步解释。
- 区分了“压缩”和“稀疏”两个动作，说明它们是乘法关系。
